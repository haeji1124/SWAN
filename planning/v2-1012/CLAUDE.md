# SWAN 웹사이트

사내 SW 교육 SWAN(SW Academy for Newbie)을 소개하고 신청받는 사내망 웹사이트. 3D와 인터랙션으로 완성도를 보여주고, 졸업생의 실제 완성작으로 "교육 후의 내 모습"을 미리 보여준다.

## 누구를 위한 서비스인가
- 예비 수강생 (타 부서 비개발자, 신입사원): 내 수준에 맞는지, 뭘 얻는지 확인한다 — 핵심 행동: 교육 신청
- 졸업생: 핵심 행동: 완성작을 갤러리에 올린다
- 보는 사람 (부서장, 실장님): 로그인 없이 랜딩과 갤러리로 교육 성과를 본다
- 관리자: 기수, 신청, 졸업생, 갤러리 검수를 관리한다

## 핵심 루프
① 쇼케이스·커리큘럼을 본다 → ② 내 수준에 맞는지 확인한다 → ③ 신청서를 제출한다
(모든 화면은 망설이는 사람이 확신을 얻어 신청하게 만드는 쪽으로 판단한다)

## 범위
- 이번에 만든다: 인트로 + 3D 랜딩, 커리큘럼, 갤러리(목록·상세·등록·수정·검수), 신청 폼과 접수 완료, 다음 기수 알림 받기(관심 등록), 관리자 화면(기수 / 신청 목록 / 졸업생 / 갤러리 검수 / 관심 등록자)
- 목업으로 처리: SSO(개발 중에는 테스트 사용자를 고르는 임시 로그인), 3D 모델(기본 도형으로 만든 임시 오리·백조), 모든 데이터(가상의 이름·사번·완성작)
- 만들지 않는다: 토이프로젝트 팀원 모집, 알림, 성과 요약, 파견/비파견 선택, 메신저·메일 발송, 신청 취소·내 신청 내역, 모바일 대응

## 기술
- 플랫폼: 데스크톱 웹 전용 (사내망 PC)
- 화면: `frontend/` — React + Vite + TypeScript + Tailwind CSS, three.js(react-three-fiber, drei), GSAP ScrollTrigger
- 서버: `backend/` — Python FastAPI + SQLite, 이미지는 서버 로컬 폴더에 저장
- 배포: 화면을 빌드해 FastAPI가 정적 파일과 `/api`를 함께 서비스한다
- 인증: 인증 부분을 한 모듈로 분리한다. 지금은 임시 로그인 구현만 있고, 나중에 사내 SSO 구현으로 바꿔 끼운다
- 데이터 모델
  - User: 사번, 이름, 부서명, 녹스 아이디, 역할(직원/관리자), 졸업 기수(없으면 비졸업생)
  - Cohort: 기수 번호, 이름, 모집·교육 기간, 활성 여부 (활성은 최대 1개)
  - Application: 사용자, 기수, 신청 시각, 상태(접수/수료) — 사용자·기수 조합당 1건
  - Interest: 사용자, 등록 시각
  - Project: 작성자, 제목, 기수, 부서, 문제 설명, 해결 방법, 효과(수치), 대표 이미지, 스크린샷 여러 장, 검수 상태(대기/승인/반려), 반려 사유
- 권한: 비로그인은 모든 화면 보기 / 로그인한 직원은 신청·관심 등록 / 졸업생은 본인 완성작 등록·수정 / 관리자는 관리자 화면 전체. 승인된 완성작만 공개한다

## 반드시 지킬 제약
- 외부 인터넷이 없는 사내망에서 돌아간다. CDN, 구글 폰트, 외부 이미지 등 실행 중에 외부로 나가는 요청을 만들지 않는다. 라이브러리·모델·글꼴·이미지를 모두 저장소에 포함한다 (three.js의 Draco·KTX2 등 보조 파일 경로도 로컬로)
- 실제 사내 정보를 넣지 않는다. 샘플 데이터는 모두 가상으로 만든다
- 비밀 값은 `.env`에 두고 커밋하지 않는다

## 디자인 원칙
- 톤: 밝음, 친근함, 장난기. 색: 물빛 파랑, 흰색, 오리 노랑(강조). 글꼴: 둥글고 읽기 쉬운 한글 고딕(파일 포함)
- 스타일: 로우폴리 3D, 둥근 모서리, 오리·백조 캐릭터 중심
- 3D 컨셉: 아기 오리가 스크롤을 따라 자라 백조가 된다 (newbie의 8주 성장)
- UX 원칙
  - 주 행동은 "신청하기" 하나. 히어로의 버튼은 작게, 페이지 끝의 버튼을 크게
  - 증거(완성작)를 설명보다 먼저 보여준다
  - 3D는 랜딩에 집중하고 정보를 읽는 화면은 깔끔한 2D로 둔다
  - 느린 PC에서는 3D 품질을 낮추고, 안 되면 정지 이미지로 대체한다. 움직임 줄이기 설정을 존중한다
- 하지 말 것: 어두운 테크 느낌, 정보 화면에 과한 3D, 모바일 대응 작업

## 작업 방식
- Phase 단위로 진행하고, 끝나면 무엇을 만들었는지와 어떻게 확인하는지 요약한다
- 기획에 없는 기능을 임의로 추가하지 말고, 필요하면 먼저 묻는다
- 화면 문구는 한국어
- 사용자는 파이썬에 익숙하고 웹 프런트와 3D는 경험이 적다. 프런트·3D 쪽 결정은 이유를 짧게 설명한다
