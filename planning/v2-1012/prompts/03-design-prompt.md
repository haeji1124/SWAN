# 디자인 프롬프트 — SWAN 웹사이트 시안 (v2: 실제 이미지 반영)

기준: 2026-10-12 기획(`기획서.md`)과 `SWAN/public/`에 있는 실제 이미지 18장. 밝고 친근한 톤, 오리 → 백조, 교육 기간 8주, 데스크톱 전용.

v1과 달라진 점
- 첨부 파일을 실제 파일명과 내용으로 바꿨다.
- 색상 값을 이미지에서 직접 뽑은 값으로 맞췄다. 이미지와 화면이 이어져 보이게 하기 위해서다.
- 마지막 장면 이미지가 노을빛이라, 랜딩이 "아침 → 한낮 → 오후 → 노을"로 흘러가는 구성을 넣었다.
- 가상 완성작 썸네일 6장에 맞춰 예시 완성작 6건을 붙였다.

사용법
1. Claude Design에서 새 디자인을 열고 아래 **첨부할 파일**을 올린다. 한 번에 다 올리기 어려우면 "프롬프트 1에 필요"라고 표시된 것부터 올린다.
2. **프롬프트 1**로 디자인 기준과 랜딩 시안을 받는다. 마음에 들면 **프롬프트 2**로 나머지 화면을 받는다.
3. **프롬프트 3~8**(수정용)로 다듬는다.
4. 확정된 시안의 화면 캡처를 `SWAN/design/`에 저장하고, 구현할 때 `claude-code-prompt.md`의 해당 Phase에 "이 시안대로"라고 함께 넣는다.

## 프롬프트 1 — 디자인 기준과 랜딩 시안

사내 SW 교육 프로그램 **SWAN**(SW Academy for Newbie)의 웹사이트를 디자인해 줘. 이번에는 **디자인 기준 한 장**과 **랜딩 화면**을 만들어 줘. 데스크톱 전용이고 기준 폭은 1440px이다. 모바일 화면은 만들지 않는다.

**이 사이트가 하는 일**
- 코딩이 처음인 사내 직원(타 부서 비개발자, 신입사원)이 모집 메일의 링크를 눌러 들어온다. 이 사람은 듣고 싶지만 "내 수준에 맞는지", "8주 뒤에 뭐가 남는지" 몰라서 신청을 망설인다.
- 사이트는 졸업생이 실제로 만든 완성작을 보여줘서 확신을 주고, 그 자리에서 교육을 신청하게 한다.
- 만든 사람의 웹 개발 역량을 보여주는 사이트이기도 해서, 사내 사이트 같지 않은 높은 완성도가 필요하다.

**컨셉: 아기 오리가 8주 뒤 백조가 된다**
- 첨부한 로우폴리 캐릭터가 사이트를 이끈다. 랜딩을 스크롤하면 아기 오리가 호수를 따라가며 자라고, 마지막 신청 버튼 앞에서 백조가 되어 날개를 편다.
- 스크롤이 곧 하루의 흐름이다: **아침(히어로) → 한낮 → 오후 → 노을(마지막)**. 첨부한 장면 4장이 이 순서대로다. 배경의 하늘과 물 색이 장면 사이에서 자연스럽게 이어지게 해 줘.
- 실제 구현에서는 랜딩 배경이 화면에 고정된 3D 장면이고 그 위로 글 섹션이 스크롤된다. 시안에서는 첨부한 장면 이미지를 구간별 배경으로 쓰고, 글은 그 위의 흰색 반투명 패널에 올려 줘.

**첨부 이미지를 쓰는 규칙**
- 장면 이미지마다 캐릭터가 있는 쪽과 비어 있는 쪽이 정해져 있다. 글 패널은 **비어 있는 쪽**에 놓고 캐릭터를 가리지 않는다: 히어로는 왼쪽, 중간 장면 1은 오른쪽, 중간 장면 2는 왼쪽, 마지막 장면은 아래쪽.
- 캐릭터를 새로 그리거나 다른 화풍의 일러스트·아이콘을 섞지 않는다. 필요한 그림은 첨부 이미지에서 가져온다.
- 스티커 6개는 회색 배경에서 잘라내 흰 테두리 스티커로 쓴다.
- 캐릭터 시트와 상태 일러스트는 하늘색 바탕(`#D8EFFF`)에 그려져 있다. 같은 색 바탕 위에 놓아 경계가 보이지 않게 한다.

**톤**
- 키워드: 밝음, 친근함, 장난기. 비개발자가 겁먹지 않아야 한다.
- 참고: soijeong.com의 전체 분위기. 캐릭터와 3D 오브젝트가 화면을 이끌고, 인트로 연출이 있고, 끌어 움직일 수 있는 스티커가 있다.
- 하지 말 것: 어두운 배경, 네온, 코드가 가득한 개발자풍 화면, 글자 위주의 딱딱한 사내 공지 느낌.

**디자인 기준 (첨부 이미지에서 뽑은 색이다. 이 값으로 시작하고, 더 나은 조합이 있으면 이유와 함께 제안해 줘)**
- 하늘 `#D8EFFF` — 일러스트가 놓이는 구역의 바탕 (이미지 배경과 같은 색)
- 옅은 하늘 `#EEF8FF` — 일반 화면 바탕
- 흰색 `#FFFFFF` — 카드, 글 패널
- 물빛 `#6DC8F4` — 주색, 장식, 보조 버튼 외곽선
- 깊은 물 `#1B6FB5` — 링크, 강조 글자, 물빛 위에 글자를 올릴 때
- 잉크 `#16324A` — 본문 글자
- 오리 노랑 `#F9C74F` — 주 행동 버튼, 강조 (캐릭터 몸 색 `#F6CD7E`보다 조금 선명하게)
- 부리 주황 `#E59560` — 작은 포인트, 오류가 아닌 주의 표시
- 노을 구역 전용: 노을 하늘 `#DBD7B2`, 노을 구름·언덕 `#B5804E`, 저녁 물 `#66A6C2` (마지막 신청 구역에서만)
- 주 행동 버튼은 오리 노랑 바탕에 잉크색 글자, 알약 모양. 보조 버튼은 흰 바탕에 물빛 외곽선과 깊은 물 글자.
- 글꼴: Pretendard 하나로 통일. 제목은 굵고 크게, 본문은 16~18px.
- 모양: 둥근 모서리(카드 24px, 버튼은 완전히 둥글게), 부드럽고 옅은 그림자, 넉넉한 여백. 로우폴리 그림과 어울리게 카드 모서리나 구분선에 각진 면 장식을 가볍게 써도 좋다.
- 글자와 배경의 대비가 충분한지 확인해 줘. 특히 물빛 위의 흰 글자, 노을 장면 위의 글자는 대비가 부족하기 쉬우니 패널이나 글자색으로 해결해 줘.

**만들 것 1: 디자인 기준 한 장**
색, 글자 크기 단계, 버튼(주·보조, 기본·올렸을 때·누를 수 없을 때), 카드, 배지(검수 대기·승인·반려, 기수), 입력 칸(기본·선택됨·오류), 상단 메뉴, 스티커 6개를 잘라낸 모습을 한 장에 정리해 줘.

**만들 것 2: 랜딩 화면 (위 → 아래)**
1. **상단 고정 메뉴**: SWAN 로고(글자), 소개 / 커리큘럼 / 갤러리, 오른쪽에 로그인과 [신청하기] 버튼. 흰색 반투명 바탕.
2. **인트로 로딩** (별도 화면 한 장): 하늘색 바탕 가운데에 `intro-egg-sheet.png`의 세 장면 중 하나와 진행률 숫자. 진행률 0%는 알, 50%는 금이 간 알, 100%는 깨어난 오리로 세 상태를 나란히 보여줘. 2초 이내로 끝나는 화면이다.
3. **히어로 — 아침** (`hero-still.png` 전체 화면): 왼쪽 빈 공간에 작은 머리글 `SW Academy for Newbie`, 제목 **처음이어도 괜찮아요.** (임시), 서브 문구 **8주 뒤, 내 업무를 덜어 주는 프로그램을 직접 만듭니다.** (임시), 작은 [신청하기] 버튼. 아래 가운데에 `스크롤해 보세요` 표시. 스티커 3개(연잎, 종이배, 머그)를 수면과 화면 가장자리에 살짝 기울여 붙이고, 구석에 작은 [원위치] 버튼. 오리는 1단계.
4. **교육 소개**: 제목 "SWAN은 이런 교육이에요". 카드 3개 — 누가 듣나요(코딩이 처음인 사내 직원) / 얼마나 하나요(8주, 한 기수 약 10명) / 뭐가 남나요(내 업무에 쓰는 완성작 하나). 카드 아래에 `character-growth-sheet.png`를 하늘색 띠 위에 놓고 단계마다 "시작 / 2주차 / 5주차 / 8주차" 라벨(임시)을 붙인다.
5. **완성작 미리보기 — 한낮** (`scene-mid-1.png`, 글 패널은 오른쪽): 제목 "졸업생들이 8주 뒤 만든 것". 완성작 카드 3장(위 표의 1, 3, 5번) — 썸네일, 제목, 기수·부서 배지, **효과 한 줄을 가장 크게**. [갤러리 전체 보기] 링크. 오리는 2단계.
6. **커리큘럼 요약**: 장면 속 징검돌에서 이어지는 느낌으로, 징검돌 8개가 한 줄로 놓이고 돌마다 주차 번호와 제목(임시). 오리가 3번째 돌쯤에 있다. [커리큘럼 자세히 보기] 링크.
7. **파트 소개 — 오후** (`scene-mid-2.png`, 글 패널은 왼쪽): 교육을 운영하는 파트 소개 글과 하는 일 3가지(임시). 오리는 3단계(처음 날개를 펴는 어린 백조).
8. **FAQ**: 흰 바탕의 차분한 구역. 접었다 펴는 질문 5개. "코딩을 처음 해도 되나요?", "8주 동안 현업은 어떻게 하나요?", "교육 후에는 무엇을 하게 되나요?"를 포함(나머지는 임시). 하나는 펼친 상태로.
9. **마지막 신청 구역 — 노을** (`final-still.png` 전체 화면): 백조 위쪽이나 양옆에 큰 제목 **다음 기수에서 만나요** (임시), 아래 빈 공간에 현재 모집 중인 기수와 교육 기간(예: 5기 · 8주), 크고 눈에 띄는 [신청하기] 버튼. 오리는 4단계(백조).
10. **바닥글**: 저녁 물 색에서 이어지는 차분한 바탕. 운영 파트와 문의처(임시).

**랜딩에서 지킬 것**
- 주 행동은 [신청하기] 하나다. 히어로의 버튼은 작게, 마지막 구역의 버튼은 크게.
- 완성작(증거)이 커리큘럼(설명)보다 먼저 온다.
- 랜딩 전체를 한 장으로 이어서 보여주고, 구간마다 시간대(아침·한낮·오후·노을)와 오리의 성장 단계를 주석으로 표시해 줘.
- 장면 이미지 사이의 이음새가 끊겨 보이지 않게, 배경색이 서서히 바뀌는 구간을 둬 줘.

## 프롬프트 2 — 나머지 화면

같은 디자인 기준으로 나머지 화면을 만들어 줘. 이 화면들은 장면 배경 없이 깔끔한 2D다. 바탕은 옅은 하늘 `#EEF8FF`, 내용은 흰 카드. 읽기와 입력이 우선이고 캐릭터는 포인트로만 쓴다. 모두 1440px 데스크톱.

1. **커리큘럼**: 제목 → 8주 타임라인(수면 위 징검돌 8개, 4주차가 선택되어 내용이 펼쳐진 상태, 선택된 돌 위에 작은 오리) → 주차별 내용 카드(배우는 것, 이 주가 끝나면 할 수 있는 것 — 내용은 임시) → "이런 분께 맞아요 / 미리 알면 좋은 것" 안내 → [신청하기].
2. **갤러리 목록**: 제목과 한 줄 설명 → 기수 필터(전체, 1기~4기) → 완성작 카드 그리드(3열 2줄). 위 표의 6건을 카드로 넣는다. 졸업생에게만 보이는 [완성작 등록] 버튼은 필터 줄 오른쪽에 둔다. 카드는 썸네일, 제목, 기수·부서 배지, 효과 한 줄. 카드 하나는 마우스를 올려 살짝 기울어진 상태로.
3. **완성작 상세** (3번 "설비 로그 이상 알리미"로): `project-placeholder-3.png`를 큰 대표 이미지로 → 제목, 만든 사람(가상 이름), 기수, 부서 → "무슨 문제를 풀었나" → "어떻게 풀었나" → 스크린샷 자리 3칸(회색 자리 표시) → 효과 수치를 아주 크게 `주 3시간 → 5분` → 다른 완성작 3장.
4. **완성작 등록**: 입력 폼 — 제목, 문제 설명, 해결 방법, 효과, 대표 이미지 올리기, 스크린샷 여러 장 올리기. 위쪽에 "관리자 검수 후 공개됩니다" 안내. [등록하기].
5. **신청**: 현재 모집 중인 기수 카드(5기, 교육 기간) → 폼(사번, 부서명, 이름, 녹스 아이디 — 미리 채워진 상태) → [신청하기]. 옆에 `character-growth-sheet.png`의 1단계 오리를 작게.
6. **신청 완료**: 하늘색 `#D8EFFF` 바탕에 `state-success.png`, "신청이 접수됐어요", 이후 일정 안내 3단계, [갤러리 둘러보기].
7. **관리자**: 탭 5개(기수 / 신청 목록 / 졸업생 / 갤러리 검수 / 관심 등록자). 캐릭터와 장식 없이 표 중심, 색은 흰색과 잉크, 물빛 포인트만.
   - 신청 목록 탭을 기본으로: 기수 선택, 표(사번, 이름, 부서명, 녹스 아이디, 신청 시각, 상태), 여러 줄 선택 후 [수료 처리], [CSV 내려받기]. 데이터는 가상.
   - 갤러리 검수 탭도 한 장: 검수 대기 목록과 미리보기, [승인] / [반려](사유 입력 창).

## 프롬프트 3 — 상태별 화면
아래 상태를 각각 작은 시안으로 만들어 줘.
- [신청하기] 버튼의 4가지 상태: 모집 중·미신청 / 이미 신청함("신청 완료") / 모집 기간 아님("다음 기수 알림 받기") / 알림 등록 완료
- "다음 기수 알림 받기" 확인 창
- 갤러리에 승인된 완성작이 0건일 때: `state-empty.png`와 "곧 졸업생들의 완성작이 올라와요" (임시)
- 내 완성작 카드의 3가지 상태: 검수 대기 / 승인 / 반려(사유 표시)
- 신청 폼에서 필수 칸이 비었을 때
- 불러오는 중: `intro-egg-sheet.png`의 금이 간 알을 작게
- 오류가 났을 때와 권한이 없는 화면에 들어왔을 때: `state-error.png`와 돌아갈 버튼

상태 일러스트는 하늘색 `#D8EFFF` 바탕 위에 놓는다.

## 프롬프트 4 — 3D를 쓸 수 없을 때의 랜딩
3D를 쓸 수 없는 PC에서는 랜딩 배경이 움직이지 않는 이미지로 바뀐다. 장면 4장(`hero-still`, `scene-mid-1`, `scene-mid-2`, `final-still`)을 구간별 고정 배경으로 쓴 랜딩 시안을 따로 만들어 줘. 내용과 버튼은 그대로이고, 움직임 없이도 "오리가 자라고 하루가 지나간다"는 이야기가 전달되어야 한다. 장면이 바뀌는 지점을 어떻게 처리할지(겹쳐서 바뀜, 구분선, 글 구역으로 끊기) 두 가지 안으로 보여줘.

## 프롬프트 5 — 더 장난스럽게 (시안이 얌전할 때)
더 장난기 있게 해 줘. soijeong.com처럼 스티커와 캐릭터가 글 패널 가장자리에 걸치거나 섹션 경계를 넘나들게 하고, 섹션 제목을 더 크게 키워 줘. 스크롤할 때 무엇이 어떻게 움직이는지 화살표와 주석으로 표시해 줘. 단, 글 읽기와 버튼 누르기를 방해하면 안 되고, 첨부 이미지 외의 새 그림은 넣지 않는다.

## 프롬프트 6 — 더 차분하게 (시안이 과할 때)
장식을 줄이고 여백을 늘려 줘. 캐릭터는 히어로, 커리큘럼, 마지막 신청 구역에만 남기고 나머지 섹션은 글과 카드만으로 정리해 줘. 스티커는 히어로에만 둔다. 부서장이나 임원이 봐도 가볍지 않게 보여야 한다.

## 프롬프트 8 — 구현 전달용 정리
확정된 시안을 구현에 넘길 수 있게 정리해 줘. 색·글자 크기·간격·모서리·그림자 값을 이름 붙인 목록으로, 화면별 블록 크기와 간격, 버튼·카드·입력 칸의 상태별 모양, 섹션이 등장할 때의 움직임(방향, 거리, 시간), 장면 배경이 바뀌는 스크롤 지점을 표로 만들어 줘. 각 이미지 파일이 어느 화면 어느 자리에 쓰였는지도 목록으로 정리해 줘.
