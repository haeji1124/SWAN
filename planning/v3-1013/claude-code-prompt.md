## Phase 0. 뼈대, 임시 로그인, 방문 기록

`SWAN/app/` 폴더에 프로젝트를 만들어 줘. 먼저 CLAUDE.md를 읽어.

**구조**
- `app/web/`: React + Vite + TypeScript + Tailwind CSS
- `app/server/`: Python FastAPI + SQLAlchemy + SQLite
- 개발 중에는 Vite가 `/api` 요청을 FastAPI로 넘기고, 배포할 때는 FastAPI가 빌드된 화면을 함께 서비스한다
- 외부 CDN과 외부 글꼴 링크를 쓰지 않는다. 글꼴은 패키지로 설치해 번들에 넣는다

**데이터베이스**
- CLAUDE.md의 데이터 모델대로 테이블을 모두 만든다
- 가상 데이터를 넣는 스크립트(`server/seed.py`)를 만든다. 모두 지어낸 이름이고 주석에 가상이라고 적는다
  - 사용자 12명 (직원 5, 5기 신청자 2, 졸업생 4, 관리자 2 — 관리자 1명은 졸업생이기도 함)
  - 기수 5개 (1~4기 종료, 5기 모집 중. 날짜는 임시)
  - 졸업생 명단 120명 (1~4기, 부서는 "공정기술 1팀", "공정기술 2팀", "설비기술팀", "품질보증팀", "수율분석팀", "설계지원팀", "기술지원팀" 같은 가상의 이름 12개에 고르게. 실제 부서 이름은 쓰지 않는다)

**임시 로그인**
- 인증은 `server/auth.py` 한곳에 모은다. 지금은 쿠키에 담긴 테스트 사용자를 읽고, 나중에 이 파일만 바꿔 SSO로 교체할 수 있게 한다
- 화면 오른쪽 아래에 개발용 "테스트 사용자 고르기" 상자를 둔다. 사용자를 고르면 그 사람으로 들어온 것처럼 동작한다. "로그인 실패" 상태도 고를 수 있다
- `GET /api/me`는 이름, 부서, 유형(직원/수강생/졸업생), 관리자 여부, 현재 기수 신청 여부를 돌려준다

**기록**
- `POST /api/events`로 방문, 섹션 도달, 클릭을 기록한다
- 화면 쪽에 `track(종류, 대상)` 함수 하나를 만들고, 사이트에 처음 들어올 때 방문을 한 번 기록한다
- 섹션 도달은 섹션이 화면에 처음 보일 때 한 번만 기록한다 (IntersectionObserver)

**공통 틀**
- 상단 고정 메뉴: 로고 · 완성작 · 커리큘럼 · 수준 테스트 · 토이프로젝트 · 아이디어 보드 · 내 이름 · 오른쪽 끝 주 행동 버튼
- 주 행동 버튼은 상태에 따라 바뀐다: [신청하기] / [신청 완료] / [다음 기수 알림 받기]. 지금은 모양만 만들고 동작은 Phase 2에서 붙인다
- 관리자에게만 [관리자] 메뉴가 보인다
- 화면 구석에 짧은 확인 메시지를 띄우는 공통 부품과, "정말 하시겠어요?"를 묻는 공통 확인 창을 만든다
- 색, 글꼴, 모서리 값은 Tailwind 테마 한곳에 모은다. 값은 방향 A(`SWAN/design/direction-a/구현-전달.md` 1장)를 처음부터 쓴다: paper `#fbfaf7` 바탕, ink `#1f2a44` 글자와 주 버튼, sky `#d6ecfb` 보조 버튼과 형광펜, line `#dfe3ea` 구분선
- 빈 화면: 홈 `/`, 완성작 `/projects`, 완성작 상세 `/projects/:id`, 완성작 올리기 `/projects/new`, 수준 테스트 `/quiz`, 신청 `/apply`, 토이프로젝트 `/toys`, 아이디어 보드 `/ideas`, 제작 과정 `/making`, 관리자 `/admin`

**확인**
- [ ] 서버와 화면을 실행하면 모든 주소가 열리고 상단 메뉴가 보인다
- [ ] 테스트 사용자를 바꾸면 상단의 이름과 [관리자] 메뉴가 바뀐다
- [ ] 페이지를 열면 EventLog에 방문 기록이 한 줄 생긴다
- [ ] 브라우저 개발자 도구의 네트워크 탭에 외부 도메인 요청이 하나도 없다

다 되면 만든 구조와 실행 방법을 요약해 줘.

## Phase 1. 홈의 10개 섹션

홈 화면을 만들어 줘. 메일의 [신청하기]를 누른 사람이 가장 먼저 보는 곳이고, 스크롤만으로 SWAN을 이해하고 신청까지 가게 하는 것이 목적이야. 업무 중에 짧게 보는 사람이라는 점을 기억해 줘.

디자인 방향은 **A 개발자의 노트**로 정했어. 색·글꼴·모서리 값(`SWAN/design/direction-a/구현-전달.md` 1장)은 지금부터 Tailwind 테마에 넣어 쓰고, 이 Phase에서는 **구성과 내용에 집중**해 줘. 줄 종이, 줄 번호, 3D 캐릭터 같은 장식은 Phase 7에서 입힌다. 섹션마다 배치를 다르게 해서 똑같은 카드 줄이 반복되지 않게 해 줘.

**섹션 (위에서 아래로, 이 순서를 지킨다)**
1. **인트로**: 화면 전체 높이. 오른쪽은 캐릭터 자리로, 지금은 정지 그림(`SWAN/design/hero-3d/duck-wave-c.png`, `instructor-tilt-c.png`)을 두고 Phase 7에서 3D로 바꾼다. 왼쪽에 메인 문구 "날개는 AI가 달아 줍니다. 나는 법은 여기서 배웁니다."와 아래로 스크롤 안내
2. **한 줄 소개**: 서브 문구 "AI 시대, SW를 보는 눈을 기릅니다." + 핵심 3가지(① 사내 환경을 아는 사내 강사 ② 주 1회 온라인, 3개월, 주 3~4시간 ③ 끝나도 물어볼 사람이 남는다) + 모집 상태("5기 모집 중, 마감 D-7" — 기수 데이터에서 계산) + [신청하기]
3. **숫자와 띠**: 기수 수, 누적 수료생 수, 참여 부서 수(졸업생 명단에서 계산) + 졸업생 이름이 가로로 흐르는 띠 + 참여 부서 이름이 반대 방향으로 흐르는 띠. 띠에 마우스를 올리면 멈춘다
4. **완성작 미리보기**: 대표 완성작 카드 4~6개. 지금은 가상 카드, Phase 4에서 실제 데이터로 연결. [완성작 전체 보기]
5. **강사 소개**: 강사는 한 명이고 남색 조끼를 입은 안경 쓴 백조 캐릭터로 표현한다(`SWAN/design/hero-3d/instructor-stand-c.png`). 이름, 하는 일, 한마디, "요청하면 직접 만날 수 있어요"
6. **커리큘럼**: 내용은 `planning/v3-1013/curriculum.md`(실제 4기 자료)를 그대로 쓴다. 주차표가 아니라 이론 5단원과 실습 프로젝트 11개다
   - 배우는 흐름 4단계: 다지기(환경 구성, 함수 활용법) → 깊어지기(파이썬 고급 개념, 알고리즘 기초, 객체지향과 디자인 패턴) → 만들기(실습 프로젝트) → **AI와 함께 만들기(바이브코딩, "5기 신설" 표시)**. 단원을 누르면 배우는 것이 펼쳐진다
   - 4단계의 단원은 `curriculum.md` 3부를 쓴다: 만들 것을 정하기 / AI에게 제대로 시키기 / AI가 짠 코드 읽고 검증하기 / 막혔을 때 빠져나오기 / 구조를 지키며 키우기 / 회사에서 안전하게 쓰기. "화면 디자인 맛보기"는 참고 항목으로 작게 둔다. 특정 도구 이름을 앞세우지 않는다
   - **실습 프로젝트 모음** (이 섹션의 중심): 11개 프로젝트를 주제 묶음(재귀와 파싱 / 탐색 알고리즘 / 아키텍처(MVP) / 객체지향·함수형 / 수학과 시각화 / 우리 업무와 닿는 과제)으로 걸러 볼 수 있다. 카드마다 미리보기 그림이나 영상 자리, 제목, 한 줄 설명, 기르는 힘. 카드를 누르면 세부 내용이 펼쳐진다. 미리보기 영상은 마우스를 올리면 재생된다
   - "모든 실습은 무엇을 만들지 미리 보여 드려요"라는 안내 한 줄
   - 교육 목표 3가지(부서에 필요한 SW 자체 개발 / 실습 위주의 제작 능력 / 재사용성 높은 SW 작성법), 수강 안내(목·금 중 주 1회 1시간 30분, 온라인, 주 3~4시간), "이런 분께 맞아요"(자동화 의지가 높은 사람 / 부서에서 SW 인력으로 키울 사람 / 주 3~4시간을 낼 수 있는 사람)
   - 단원은 CurriculumUnit, 프로젝트는 PracticeProject에서 읽는다. `curriculum.md`의 내용을 seed에 넣는다. 미리보기 그림과 영상은 아직 없으니 자리 그림을 쓴다
   - 바이브코딩 단원의 세부 내용은 잠정이다. `curriculum.md` 3부에 없는 단원을 지어내지 않는다
7. **수준 테스트 안내**: "3분이면 내 수준을 알 수 있어요" + 성장 단계 세 개의 그림 자리 + [테스트 시작하기]
8. **파트 소개**: Design Technology팀 IPS 파트가 하는 일, 만든 것들(가상 3개) + [아이디어 남기기]
9. **아이디어 보드 미리보기**: 공감 많은 아이디어 3개(지금은 가상) + [아이디어 보드 보기]
10. **마지막 신청 안내**: 마무리 문구, 모집 마감일, [신청하기], "이 사이트는 바이브코딩으로 만들었습니다 →" (제작 과정으로)

**움직임**
- GSAP ScrollTrigger로 섹션이 화면에 들어올 때 아래에서 올라오며 나타난다

**기록**

**수용 기준**

## Phase 2. 신청과 취소, 기수 관리, 신청자 목록, 졸업생 명단

이 사이트의 핵심 행동인 "교육 신청"을 만들어 줘. 확신이 든 사람이 10초 만에 끝낼 수 있어야 해. 이 Phase가 끝나면 5기 모집을 실제로 받을 수 있어야 해.

**신청 화면 `/apply`**
- 기수 정보: 5기, 모집 기간, 개강일, 강의 요일과 시간, "주 3~4시간이 필요해요"
- 신청서는 두 칸뿐: 파이썬을 써 본 경험(거의 없음 / 간단한 스크립트 / 업무에 꾸준히 사용 중 하나 고르기), 만들고 싶은 것 또는 자동화하고 싶은 업무(한두 줄, 선택)
- 이름, 부서, 사번은 화면에 보여주지 않고 로그인 정보로 뒤에서 저장한다
- [신청하기]를 누르면 접수 완료 화면: 축하 연출 자리, "5기 신청이 접수됐어요", 내 이름·부서와 신청 일시, 개강까지 남은 날, [완성작 구경하기], [홈으로]

**상태에 따른 동작**
| 상태 | 주 행동 버튼 | 누르면 |
|---|---|---|
| 모집 중, 아직 신청 안 함 | [신청하기] | 신청 화면으로 |
| 모집 중, 이미 신청함 | [신청 완료] | "신청을 취소할까요?" 확인 창 → 확인하면 취소 |
| 모집 기간이 아님 | [다음 기수 알림 받기] | Interest에 등록, "알림을 신청했어요". 이미 등록했으면 [알림 신청됨] |
| 로그인 실패 | [신청하기] | "로그인이 필요해요" 안내 |

- 한 사람은 한 기수에 유효한 신청이 한 건뿐이다. 서버에서도 막는다
- 취소한 뒤에는 다시 신청할 수 있다
- 선발이 없다. 신청하면 수강 확정이다

**관리자 화면 `/admin`** (왼쪽 메뉴, 오른쪽 내용. 관리자만 들어올 수 있고 서버에서도 막는다)
- **기수**: 목록, [기수 추가], [수정], [모집 열기/닫기]. 모집 중인 기수는 하나만 가능
- **신청자**: 기수별 표(이름, 부서, 신청 일시, 파이썬 경험, 만들고 싶은 것, 수준 테스트 결과 — 테스트 열은 Phase 3에서 채움), 취소한 사람은 따로 표시, [엑셀로 내려받기]
- **졸업생**: 기수별 표, [엑셀로 올리기](이름, 부서, 기수, 사번 열. 올리기 전에 미리보기와 건수를 보여주고 확인), [수료 처리](끝난 기수의 신청자를 졸업생 명단으로 옮김)
- 나머지 메뉴(완성작 검수, 토이프로젝트, 아이디어, 수준 테스트, 커리큘럼, 관리자)는 자리만 만든다

**수용 기준**
- [ ] 신청 → 접수 완료 → 버튼이 [신청 완료]로 바뀐다
- [ ] [신청 완료]를 누르면 취소를 묻고, 취소하면 [신청하기]로 돌아간다
- [ ] 같은 사람이 두 번 신청할 수 없다 (화면과 서버 모두)
- [ ] 관리자가 모집을 닫으면 모든 사람의 버튼이 [다음 기수 알림 받기]로 바뀐다
- [ ] 신청자 명단을 엑셀로 내려받을 수 있다
- [ ] 졸업생 엑셀을 올리면 홈의 숫자와 이름 띠가 바뀐다
- [ ] 관리자가 아닌 사람은 `/admin`에 들어갈 수 없다

**확인**: 테스트 사용자 세 명으로 번갈아 신청·취소해 보고, 관리자로 들어가 명단을 내려받는다. 모집을 닫고 다시 직원으로 들어가 본다.
다 되면 요약해 줘.

## Phase 3. 수준 테스트

"내 수준이 이 강의에 맞나?"에 3분 만에 답하는 수준 테스트를 만들어 줘. 목적은 걸러 내기가 아니라 확신 주기야. 마지막 문제는 이 사이트의 핵심 메시지인 "AI가 짠 코드를 판단하는 눈"을 직접 체험하게 하는 하이라이트야.

**흐름 `/quiz`**
1. **시작**: "3분이면 내 수준을 알 수 있어요", 문제 6개, 안내 문구 "결과는 교육 운영에 참고하기 위해 기록됩니다. 신청한 분은 모두 수강할 수 있으니 편하게 풀어 보세요." [시작하기]
2. **문제 1~4** (보기 고르기): 진행 표시(2/6), 코드 한 덩어리, 질문, 보기 4개. 고르면 [다음]
3. **문제 5** (주관식): 코드와 "출력되는 그대로 적어 주세요", 입력 칸 하나. 채점할 때 앞뒤 공백과 따옴표는 무시한다
4. **문제 6** (줄 고르기): 위에서 아래로 — 상황 설명("에러를 붙여넣고 고쳐 달라고 했더니 AI가 이렇게 고쳤어요. 이제 에러 없이 숫자가 나옵니다") → 원래 에러 메시지(고정폭, 주황) → 로그 파일 내용 → AI가 고친 코드(줄 번호 있음) → "결과를 틀리게 만드는 줄을 클릭하세요." **줄을 직접 클릭해서 하나 고른다**. [제출하기]
   - 정답 줄은 1점. 부분 정답 줄(`except Exception:`, `pass`)은 0점이지만 결과 화면에서 "절반 맞았어요. 더 직접적인 원인이 있어요"라고 알린다
5. **결과**: 성장 단계 그림 자리와 메시지, 맞힌 개수

| 결과 | 단계 | 메시지 | 버튼 |
|---|---|---|---|
| 5~6개 | 어린 백조 | "지금 딱 SWAN이 필요한 단계예요. 고급까지 함께 가요." | [신청하기] |
| 3~4개 | 아기 오리 | "기초는 있어요. 복습 시간을 조금 더 잡으면 충분히 따라올 수 있어요." | [신청하기] |
| 0~2개 | 알에서 나온 오리 | "지금은 기초를 먼저 다지는 걸 추천해요." + 추천 기초 자료(가상 3개) | [다음 기수 알림 받기], [그래도 신청하기] |

6. **해설**: 문제별 내 답, 정답, 짧은 해설(접혀 있고 누르면 펼쳐짐). 문제 6의 해설은 펼친 상태로 보여준다: 내가 고른 줄과 정답 줄을 코드 위에 색으로 표시 → "실제로 돌린 결과" 표(나와야 할 값 80.0 / 이 코드의 값 48.0, 열 이름이 바뀌면 0.0) → 더 나은 코드 → 마무리 문구 "에러가 사라졌다고 문제가 사라진 건 아닙니다. AI가 고친 코드가 「돌아가는지」가 아니라 「맞는지」를 보는 눈, SWAN에서 기릅니다." [다시 풀기]

**규칙**
- 어떤 결과가 나와도 신청을 막지 않는다
- 다시 풀 수 있다. 응시할 때마다 기록하되, 첫 응시에 표시를 남겨 기준 기록으로 쓴다
- 누가 어떤 문제에 무엇을 골랐는지까지 저장한다
- 로그인 실패 상태에서는 풀 수 있지만 기록하지 않는다
- 이미 신청한 사람의 결과 화면에서는 [신청하기] 대신 "이미 신청하셨어요"

**문제 데이터**
- 문제 6개는 `planning/v3-1013/level-test.md`의 내용을 그대로 seed에 넣는다 (문제, 코드, 보기, 정답, 해설, 더 나은 코드. 6번은 후보 A). 이 문서의 코드는 모두 실제로 돌려 정답을 확인한 것이다. 나중에 강사와 검토해 관리자 화면에서 바꿀 수 있다
- 코드는 고정폭 글꼴로, 문법에 따라 색을 입혀 보여준다 (외부 서비스 없이 번들에 포함된 라이브러리로)

**관리자**
- **수준 테스트 메뉴**: 문제 목록, [문제 추가/수정](유형: 보기 고르기/주관식/줄 고르기, 상황 설명, 코드, 질문, 보기, 정답, 부분 정답 줄, 해설, 더 나은 코드), 응시 결과 표(이름, 부서, 첫 응시 점수, 응시 횟수, 문제별 정답 여부)
- 신청자 목록의 "수준 테스트 결과" 열을 첫 응시 점수로 채운다

**기록**: 테스트 시작, 문제별 진행, 완료, 결과 화면의 버튼 클릭을 기록한다

**수용 기준**
- [ ] 6문제를 풀면 맞힌 개수에 맞는 결과가 나온다
- [ ] 문제 5에 답을 적을 수 있고, `"1234"`, ` 1234 `도 정답으로 채점된다
- [ ] 문제 6에서 코드의 줄을 클릭해 고를 수 있고, 고른 줄이 표시된다. `count += 1`이면 정답, `except`나 `pass`면 "절반 맞았어요"
- [ ] 문제 6의 해설에서 고른 줄과 정답 줄이 코드 위에 색으로 표시된다
- [ ] 결과가 낮아도 신청할 수 있다
- [ ] 다시 풀어도 첫 응시 기록이 유지된다
- [ ] 관리자가 문제를 고치면 바로 반영된다
- [ ] 홈의 [테스트 시작하기]와 상단 메뉴에서 들어올 수 있다

**확인**: 일부러 다 틀려 보고, 다 맞혀 보고, 중간쯤 맞혀 본다. 관리자로 들어가 응시 결과 표를 본다.
다 되면 요약해 줘.

## Phase 4. 완성작 갤러리

졸업생이 만든 완성작을 보여주는 갤러리를 만들어 줘. "교육 뒤의 내 모습"을 같은 부서 사람의 결과물로 보여주는, 이 사이트에서 가장 설득력 있는 증거야.

**갤러리 목록 `/projects`**
- 제목과 완성작 수 → 기수·부서 필터, 정렬(최신순·좋아요순) → 카드 그리드 → 졸업생에게만 [완성작 올리기]
- 카드: 대표 이미지와 좋아요 수가 보이고, **마우스를 올리면 짧은 설명이 나타나며**, 클릭하면 상세로 들어간다
- 공개된 완성작만 보인다
- 하나도 없을 때: "곧 졸업생들의 작품이 걸립니다" 빈 상태

**완성작 상세 `/projects/:id`**
- 대표 이미지 → 제목, 만든 사람(**이름, 부서, 기수를 모두 표시**), 좋아요 버튼 → 무슨 문제를 풀었나 → 효과 → 화면 캡처(누르면 크게) → 발표자료 보기 → 자세한 설명 → 저장소 주소 → "나도 이런 걸 만들고 싶다면" [신청하기] → 같은 부서·같은 기수의 다른 완성작
- 좋아요: 로그인한 사람만, 한 사람이 한 번. 다시 누르면 취소. 누르는 순간 숫자가 바뀌고 작은 반응이 있다

**완성작 올리기 `/projects/new`** (졸업생만)
- 맨 위 안내 문구:
  > **올리기 전에 확인해 주세요**
  > 등록한 완성작은 관리자 승인을 거쳐 사내 모든 임직원에게 공개됩니다.
  > 화면 캡처나 설명에 공정 조건, 장비 정보, 수율, 고객사·제품명처럼 민감한 내용이 보이면 지우거나 가린 뒤 올려 주세요.
  > 가리기 어려우면 실제 데이터 대신 예시 데이터로 바꾼 화면을 써도 좋습니다.
- 입력 칸

| 칸 | 필수 | 형식 |
|---|---|---|
| 제목 | 필수 | 한 줄 |
| 짧은 설명 | 필수 | 한두 줄 (카드 호버에 쓰임, 80자 제한) |
| 대표 이미지 | 필수 | 이미지 한 장 |
| 무슨 문제를 풀었나 | 필수 | 여러 줄 |
| 효과 | 선택 | 한 줄 (예: 주 2시간 → 5분) |
| 화면 캡처 | 선택 | 이미지 여러 장 |
| 발표자료 | 선택 | PDF 또는 PPT 한 개 |
| 저장소 주소 | 선택 | 주소 |
| 자세한 설명 | 선택 | Toast UI Editor |

- "민감한 내용이 없는지 확인했습니다"에 체크해야 [올리기]를 누를 수 있다
- 올린 뒤에는 내 완성작에 "승인 대기 중"이 표시된다. 반려되면 이유를 보고 고쳐서 다시 올린다. 내 완성작은 수정하고 지울 수 있다(지울 때는 한 번 더 묻는다). 공개된 완성작을 수정하면 다시 승인 대기로 돌아간다
- 파일은 서버 폴더에 저장하고, 종류와 크기를 서버에서 확인한다

**관리자 — 완성작 검수 메뉴**
- 승인 대기 목록 → 내용 미리보기(공개됐을 때와 같은 모습), 발표자료 열기 → [승인] / [반려](이유를 꼭 적는다)
- 공개된 완성작을 다시 내릴 수 있다

**홈 연결**: 홈의 완성작 미리보기를 실제 데이터로 바꾼다 (좋아요가 많은 순으로 4~6개)

**가상 데이터**: 공개된 완성작 6개(기수마다 최소 1개), 승인 대기 1개, 반려 1개. 대표 이미지는 `SWAN/public/project-placeholder-1~6.png`를 쓴다

**수용 기준**
- [ ] 카드에 마우스를 올리면 짧은 설명이 나타난다
- [ ] 기수·부서 필터와 정렬이 동작한다
- [ ] 졸업생이 올리면 승인 대기가 되고, 관리자가 승인해야 목록에 나온다
- [ ] 반려하면 올린 사람에게 이유가 보인다
- [ ] 확인 체크 없이는 올릴 수 없다
- [ ] 좋아요는 한 사람이 한 번이고, 로그인 실패 상태에서는 안내가 나온다
- [ ] 졸업생이 아닌 사람에게는 [완성작 올리기]가 보이지 않고, 주소로 직접 들어가도 막힌다

**확인**: 졸업생으로 올리고 → 관리자로 반려 → 졸업생으로 고쳐 다시 올리고 → 관리자로 승인 → 직원으로 좋아요.
다 되면 요약해 줘.

## Phase 5. 아이디어 보드와 토이프로젝트

두 개의 게시판을 만들어 줘. 둘 다 "가볍게 올린다"가 핵심이라 승인 없이 바로 공개돼.

**아이디어 보드 `/ideas`** — 사내 모든 직원이 남긴다
- 부서장님을 거치는 공식 요청은 무거워서 작은 불편은 말을 못 꺼낸다. 그 불편을 가볍게 던지는 창구다
- 정렬(공감순·최신순) → 아이디어 카드(제목, 설명, 올린 사람, 공감 수, 상태, 파트 답변) → [나도 필요해요]
- [아이디어 남기기]: 제목, 설명(두세 줄), 이름 표시 방식(이름과 부서 / 부서만) 고르기. 칸은 이것뿐이다
- 올린 사람 표시는 고른 방식대로. 어느 쪽이든 관리자 화면에서는 이름이 보인다
- 공감은 한 사람이 한 번, 다시 누르면 취소
- 상태: 접수됨 → 검토 중 → 만드는 중 → 완료 / 보류
- 내가 올린 아이디어는 수정하고 지울 수 있다
- 하나도 없을 때의 빈 상태
- **관리자 — 아이디어 메뉴**: 목록(공감 수 포함), [상태 변경], [답변 쓰기](한 줄), [숨기기]

**토이프로젝트 `/toys`** — 수강생과 졸업생끼리
- 혼자 막혔을 때 물어볼 사람을 만나는 곳이다
- 누구나 볼 수 있지만, 글쓰기와 참여는 수강생과 졸업생만 할 수 있다
- 모집 글 목록(제목, 만들 것, 필요한 인원, 모집 상태) → [모집 글 쓰기]
- 모집 글 쓰기: 제목, 만들고 싶은 것, 필요한 역할과 인원, 예상 기간
- 글 상세: 내용, [참여하고 싶어요](누르면 글쓴이에게 내 이름과 부서가 전달된다. 다시 누르면 취소)
- 글쓴이만 참여 희망자 목록을 본다. 글쓴이가 [모집 마감]을 할 수 있다
- **관리자 — 토이프로젝트 메뉴**: 목록, [숨기기]

**홈 연결**: 홈의 아이디어 보드 미리보기를 실제 데이터로 바꾼다 (공감 많은 순 3개)

**가상 데이터**: 아이디어 8개(상태를 고르게, 답변 달린 것 3개), 모집 글 3개

**수용 기준**
- [ ] 직원이 아이디어를 남기면 바로 목록에 보인다
- [ ] 이름 표시 방식에 따라 올린 사람이 다르게 보인다
- [ ] 관리자가 상태를 바꾸고 답변을 쓰면 카드에 보인다
- [ ] 관리자가 숨기면 목록에서 사라진다
- [ ] 일반 직원에게는 토이프로젝트 글쓰기와 참여 버튼이 보이지 않는다
- [ ] 글쓴이만 참여 희망자 목록을 본다

**확인**: 직원으로 아이디어를 남기고 다른 직원으로 공감 → 관리자로 상태 변경과 답변. 졸업생으로 모집 글 → 수강생으로 참여 → 졸업생으로 희망자 확인.
다 되면 요약해 줘.

## Phase 6. 제작 과정 화면, 커리큘럼 관리, 관리자 추가

남은 기능을 마무리해 줘.

**제작 과정 `/making`**
- "이 사이트도 바이브코딩으로 만들었다"를 과정과 함께 보여주는 화면이다. SWAN에서 배우면 이런 것을 만들 수 있다는 가장 가까운 증거다
- 위에서 아래로
  1. 머리말: "이 사이트는 바이브코딩으로 만들었습니다" + 한 줄 요약(만든 사람, 걸린 기간, 쓴 도구)
  2. 숫자로 보는 제작: 걸린 기간, AI와 나눈 대화 수, 화면 수
  3. 제작 타임라인: 기획 → 화면 구조 → 디자인 → 구현 → 다듬기. 단계마다 무엇을 했는지 짧게. 기획 단계에는 "AI와 질문과 답으로 기획했고, 세 번에 걸쳐 방향이 바뀌었다"를 담는다
  4. 실제로 쓴 프롬프트: 단계별 대표 프롬프트. "이렇게 시켰더니" → "이게 나왔다"를 화면 그림과 나란히. 긴 프롬프트는 접어 두고 [펼쳐 보기], [복사하기]. 맨 아래에 [전체 프롬프트 보기]
  5. **막혔던 순간과 해결** (가장 중요): AI가 틀린 결과를 냈을 때 무엇을 보고 어떻게 바로잡았는지. 이 대목이 없으면 "AI가 다 해 주네, 교육이 왜 필요하지?"로 끝난다
  6. SWAN에서 배우는 것과의 연결: "이 과정에서 쓴 방법을 SWAN의 'AI와 함께 만들기' 단원에서 다룹니다" (기획 → 만들 것을 정하기, 프롬프트 → AI에게 제대로 시키기, 막혔던 순간 → AI가 짠 코드 읽고 검증하기에 각각 연결)
  7. [신청하기]
- 내용은 `web/src/content/making.md` 같은 파일 하나에서 읽어 오게 해서, 코드를 고치지 않고 글만 바꿀 수 있게 한다
- 지금은 `planning/v3-1013/build-log.md`와 planning 폴더의 프롬프트 파일을 참고해 초안을 채운다. **부서 이름 같은 사내 정보는 넣지 않는다.** 확정되지 않은 숫자는 비워 두고 표시한다

**관리자 — 커리큘럼 메뉴**
- 단원(단계, 제목, 배우는 것)을 수정한다
- 실습 프로젝트를 추가·수정·삭제하고 순서를 바꾼다 (제목, 한 줄 설명, 세부 내용, 주제 묶음, 기르는 힘, 미리보기 그림과 영상 올리기)
- 홈의 커리큘럼 섹션에 바로 반영된다

**관리자 — 관리자 메뉴**
- 관리자 목록, [추가](사번이나 이름으로 찾아서), [해제]. 자기 자신은 해제할 수 없다

**수용 기준**
- [ ] 제작 과정 화면이 7개 구획으로 구성돼 있고 프롬프트를 펼치고 복사할 수 있다
- [ ] 내용 파일만 고쳐도 화면이 바뀐다
- [ ] 관리자가 단원과 실습 프로젝트를 고치면 홈에 반영된다
- [ ] 관리자를 추가하고 해제할 수 있다

**확인**: 홈 맨 아래의 "이 사이트는 바이브코딩으로 만들었습니다"에서 제작 과정으로 들어가 본다.
다 되면 요약해 줘. 이로써 모든 기능이 완성된다.

## Phase 7. 디자인 방향 A 적용과 3D 캐릭터

> 방향 A(개발자의 노트)로 정했다 (2026-10-16). 기준 문서는 `SWAN/design/direction-a/구현-전달.md`, 화면 시안은 Claude Design 프로젝트의 A 파일들, 첫 화면 배치는 `SWAN/design/hero-3d/hero-a.png`.

`SWAN/design/direction-a/구현-전달.md`와 시안대로 사이트 전체에 디자인을 입혀 줘.

- 테마 값이 구현 전달 1장과 같은지 다시 맞춘다. 글꼴 세 개(NanumSquareRound, Pretendard, JetBrains Mono) 파일을 번들에 넣는다
- 홈의 10개 섹션을 시안대로 다시 짠다. 미색 종이의 가는 줄, 왼쪽 줄 번호, `//` 주석, 하늘색 형광펜. 장식은 첫 화면에서만 넉넉히 쓰고 나머지 화면에서는 아낀다
- 캐릭터 그림을 제자리에 넣는다: 강사 소개(백조), 수준 테스트의 성장 단계 세 개(`SWAN/design/stages-3d/stage-*-c.png`, 나란히 선 그림 `stages-lineup-c.png`), 신청 완료, 빈 상태
- **3D 캐릭터** (홈 인트로 오른쪽, 하늘색 연못 위의 오리와 강사 백조): `SWAN/design/3d/duckling-v2/duckling-v2-rigged.glb`, `SWAN/design/3d/instructor/instructor-rigged.glb`를 react-three-fiber로 띄운다
  - 두 파일에 움직임 네 개가 들어 있다: `idle`(숨쉬기, 반복) · `wave`(손 흔들기) · `tilt`(갸웃) · `hop`(뛰기)
  - 평소에는 둘 다 `idle`. 처음 들어오면 오리가 `wave` 한 번. 백조를 누르면 `tilt`, 오리를 누르면 `hop`. 마우스 쪽으로 고개를 살짝 돌린다
  - 넣기 전에 파일을 줄인다(면 수 절반, 텍스처 1024px, 각 1~1.5MB)
  - 느린 PC, WebGL 없음, 움직임 줄이기 설정이면 정지 그림(`SWAN/design/hero-3d/duck-wave-c.png`, `instructor-tilt-c.png`)으로 바꾼다. 실행 중 프레임 속도를 재서 낮으면 자동으로 바꾼다
  - 3D는 홈 인트로와 신청 접수 완료(오리 `hop`) 두 곳에만 쓴다
- 영상 인트로는 지금 넣지 않는다. 3D 캐릭터가 첫 화면의 움직임을 맡는다 (영상이 필요한지는 `TODO.md`에서 따로 정한다)
- 움직임: 섹션 등장, 카드 호버, 좋아요와 공감의 작은 반응, 신청 완료의 축하 연출
- 운영체제의 "움직임 줄이기" 설정을 따른다
- 신청, 수준 테스트, 관리자처럼 정보를 읽는 화면은 장식 없이 깔끔하게 둔다
- 하지 말 것: 그라디언트, 빛 번짐, 반투명 유리 카드, 똑같은 카드 줄의 반복, 제목 위의 작은 영어 대문자 라벨, 이모지 아이콘

**확인**: 시안과 나란히 놓고 비교한다. 1440×900과 1920×1080에서 본다.
다 되면 시안과 다르게 만든 부분이 있으면 이유와 함께 알려 줘.

## Phase 8. 다듬기와 사내망 반입 준비

- **상태 점검**: 모든 목록의 빈 상태, 불러오는 중, 오류 상태. 권한이 없는 주소로 들어갔을 때의 안내
- **외부 연결 점검**: 네트워크를 끊고 모든 화면이 뜨는지 확인한다. 3D 관련 파일, 편집기, 글꼴이 모두 사이트 안에서 불러와지는지 본다
- **성능**: 1440×900에서 홈 스크롤이 끊기지 않는지, 영상과 3D가 있는 구간의 프레임 속도
- **접근성**: 키보드만으로 신청과 수준 테스트를 끝낼 수 있는지, 글자 대비, 버튼 이름
- **SSO 교체 안내서**: `server/auth.py`에서 무엇을 바꾸면 되는지 `docs/sso.md`로 정리한다. 개발용 "테스트 사용자 고르기" 상자를 끄는 설정을 만든다
- **반입 안내서**: `docs/deploy.md` — 화면 빌드, 서버 실행, 필요한 패키지 목록(npm, 파이썬)과 인터넷 없이 설치하는 방법, 데이터베이스 초기화, 가상 데이터 없이 시작하는 방법
- **실제 데이터 넣는 순서**: 관리자 지정 → 기수 → 졸업생 명단 엑셀 → 커리큘럼 → 수준 테스트 문제 → 기수별 완성작 1개씩

**확인**: 빈 데이터베이스로 시작해 반입 안내서대로 따라 해 본다.
다 되면 남은 문제와 함께 요약해 줘.

## 부록: 기획 근거 요약
- **문제**: 파이썬은 쓸 줄 알지만 AI가 짠 코드가 맞는지 판단하지 못하고, 한 부분에서 막혀도 물어볼 사람이 없다. 기존 교육은 온라인이거나 사외이고 강사가 사내 환경을 모른다.
- **궁극적 페인포인트**: "AI가 코드를 짜 줘도, 그 코드가 맞는지 판단할 눈이 없다."
- **SWAN의 자리**: 사내 환경을 아는 사내 강사가 가르치고, 코드를 볼 줄 아는 눈을 길러 주며, 막혔을 때 물어볼 사람이 생기는 곳.
- **목표 지표**: 5기 신청 65명 안팎 · 갤러리 완성작 기수마다 1개씩 4개 이상 · 아이디어 3개 이상
- **근거 수치**: 개발자의 66%가 "거의 맞지만 딱 맞지는 않는 AI 답"을 겪는다 (Stack Overflow 2025 Developer Survey)
- 구현 중 판단이 애매하면: **망설이던 사람이 눈으로 보는 증거로 확신을 얻어 그 자리에서 신청하게 되는가**로 정한다.
