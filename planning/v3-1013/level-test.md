상태: Claude 초안 (2026-10-14). 6번은 후보 A로 확정(사용자). 문제 내용은 부장님·강사와 검토 후 확정한다.
모든 코드는 Python 3에서 실제로 돌려 정답을 확인했다.

## 구성
| # | 형식 | 보는 것 | 커리큘럼과의 연결 |
|---|---|---|---|
| 1 | 객관식 | 리스트는 복사가 아니라 같은 것을 가리킨다 | 파이썬 고급 개념 (객체와 참조) |
| 2 | 객관식 | 딕셔너리와 `max(key=)` | 함수 활용법 |
| 3 | 객관식 | `map`, `filter`, `lambda` | 함수 활용법 (map/reduce) |
| 4 | 객관식 | 함수 기본값의 함정 | 파이썬 고급 개념 |
| 5 | **주관식** | 재귀 함수의 실행 순서 | 알고리즘 기초 (재귀) |
| 6 | **AI가 짠 코드 보기 (줄 클릭)** | 에러를 고쳐 달라고 했더니 에러를 숨긴 코드. 돌아는 가는데 결과가 틀린 줄을 찾는다 | 바이브코딩 단원: AI가 짠 코드 읽고 검증하기 |

- 1~5는 "이 과정을 따라올 준비가 됐는가"를 본다. 교육에서 배울 closure, decorator, generator는 묻지 않는다
- 6은 문법이 아니라 **구조**를 본다. 문법 오류나 오타가 아니라, 잘 돌아가는 코드에 숨은 설계 문제를 찾는다
- 결과: 5~6개 → 어린 백조 / 3~4개 → 아기 오리 / 0~2개 → 알에서 나온 오리

## 문제 1 (객관식)
다음 코드를 실행하면 무엇이 출력될까요?

```python
a = [1, 2, 3]
b = a
b.append(4)
print(len(a))
```

① 3　② **4**　③ 에러　④ None

**해설**: `b = a`는 리스트를 복사하지 않습니다. `a`와 `b`는 같은 리스트 하나를 가리키는 두 개의 이름이에요. 그래서 `b`에 넣은 4가 `a`에도 보입니다. 복사하려면 `b = a.copy()`라고 써야 합니다.

## 문제 2 (객관식)
다음 코드를 실행하면 무엇이 출력될까요?

```python
scores = {"kim": 80, "lee": 95, "park": 70}
best = max(scores, key=scores.get)
print(best)
```

① 95　② **lee**　③ ('lee', 95)　④ park

**해설**: 딕셔너리를 그대로 `max`에 넣으면 키를 비교합니다. `key=scores.get`은 "키를 비교할 때 그 키의 값으로 비교하라"는 뜻이에요. 그래서 값이 가장 큰 키인 `lee`가 나옵니다. 키 자체를 알파벳순으로 비교했다면 `park`이 나왔을 거예요.

## 문제 3 (객관식)
다음 코드를 실행하면 무엇이 출력될까요?

```python
nums = [1, 2, 3, 4]
result = list(map(lambda x: x * 2, filter(lambda x: x % 2 == 0, nums)))
print(result)
```

① [2, 4, 6, 8]　② **[4, 8]**　③ [2, 6]　④ [1, 2, 3, 4]

**해설**: 안쪽부터 읽습니다. `filter`가 짝수 `[2, 4]`만 남기고, `map`이 그것을 두 배로 만들어 `[4, 8]`이 됩니다. 이렇게 함수를 이어 붙이는 방식을 SWAN의 "함수 활용법" 단원에서 다룹니다.

## 문제 4 (객관식)
다음 코드를 실행하면 무엇이 출력될까요?

```python
def add(item, box=[]):
    box.append(item)
    return box

add(1)
print(add(2))
```

① [2]　② **[1, 2]**　③ [1]　④ 에러

**해설**: 함수의 기본값 `[]`은 함수를 부를 때마다 새로 만들어지지 않습니다. 함수가 처음 정의될 때 한 번만 만들어지고 계속 같은 리스트가 쓰여요. 그래서 첫 번째 호출에서 넣은 1이 남아 있습니다. AI가 짠 코드에서도 자주 보이는 실수예요. 고치려면 `box=None`으로 두고 함수 안에서 `if box is None: box = []`라고 씁니다.

## 문제 5 (주관식)
다음 코드를 실행하면 무엇이 출력될까요? 출력되는 그대로 적어 주세요.

```python
def f(n):
    if n == 0:
        return ""
    return f(n - 1) + str(n)

print(f(4))
```

**정답**: `1234`
- 채점: 앞뒤 공백과 따옴표는 무시한다. `"1234"`, `'1234'`, ` 1234 `는 모두 정답

**해설**: `f(4)`는 `f(3) + "4"`이고, `f(3)`은 `f(2) + "3"`이고, … `f(0)`은 빈 문자열입니다. 가장 안쪽부터 채워지면서 `"" + "1" + "2" + "3" + "4"`가 돼요. 그래서 `4321`이 아니라 `1234`입니다. 재귀는 "먼저 부른 것이 나중에 끝난다"는 순서를 머릿속에 그릴 수 있어야 해요. SWAN의 "알고리즘 기초" 단원과 Equation parser 실습에서 깊이 다룹니다.

**왜 주관식인가**: 보기가 있으면 `1234`와 `4321` 중에서 감으로 고를 수 있어요. 직접 적게 하면 실행 순서를 정말 따라갔는지가 드러납니다.

## 문제 6 — 후보 A로 확정 (2026-10-14)

AI가 실제로 자주 내는 결과 중 "돌아는 가는데 틀렸거나, 느리거나, 나중에 무너지는" 유형을 찾아 문제로 만들었다. 문법 오류는 넣지 않았다. 모든 코드는 실제로 돌려 결과를 확인했다.

**근거로 삼은 자료**
- AI가 짠 코드는 행복한 경로(정상 입력)는 잘 만들지만 오류 경로에 약하고, 에러를 드러내기보다 덮어 버리는 경향이 있다는 지적: [AIRA: AI-Induced Risk Audit (arXiv 2604.17587)](https://arxiv.org/pdf/2604.17587), [Testing and Debugging AI-Generated Code](https://www.softwareseni.com/testing-and-debugging-ai-generated-code-systematic-strategies-that-work/) — 논문의 설명(보상 구조 때문이라는 것)은 가설이고, 수치는 원문 확인 전
- AI가 짠 코드의 비효율 중 논리와 성능 문제가 가장 흔하다는 분류 연구: [Unveiling Inefficiencies in LLM-Generated Code (ICSME 2025)](https://arxiv.org/html/2503.06327v1)
- 기능은 맞아도 사람이 짠 코드보다 느린 경우가 잦다는 연구: [EMSE 2026](https://ece.uwaterloo.ca/~wshang/pubs/EMSE_2026_SHUANG_LI.pdf)
- 참고: 없는 패키지를 지어내는 비율이 상용 모델 5.2% 이상, 공개 모델 21.7%라는 연구: [We Have a Package for You! (USENIX Security 2025)](https://www.usenix.org/conference/usenixsecurity25/presentation/spracklen) — 실행하면 바로 드러나서 "읽는 눈" 문제로는 쓰지 않았다

### 확정: 후보 A — 에러를 고쳐 달라고 했더니, 에러를 숨겼다

**왜 추천하나**: 기획에서 정한 페인포인트가 "AI에게 에러를 붙여넣고 고쳐 달라는 반복"이었다. 이 문제는 그 장면 그대로다. 그리고 문제가 **한 줄에 모여 있어서** 처음 정한 "틀린 줄 직접 클릭" 방식을 그대로 쓸 수 있다.

**상황**
설비 로그에서 평균 온도를 구하는 코드를 돌렸더니 이런 에러가 났습니다.
```
ValueError: could not convert string to float: 'N/A'
```
에러 메시지를 AI에게 붙여넣고 "고쳐 줘"라고 했더니, AI가 아래처럼 고쳤어요. **이제 에러 없이 숫자가 나옵니다.**

```python
import csv

def average_temp(path):
    total = 0
    count = 0
    with open(path, encoding="utf-8") as f:
        for row in csv.DictReader(f):
            try:
                total += float(row["temp"])
            except Exception:
                pass
            count += 1
    return total / count
```

로그 파일은 이렇게 생겼습니다.
```
temp
80
82
N/A
78
-
```

**질문 (줄 클릭형)**: 이 코드를 그대로 쓰면 결과가 틀립니다. **결과를 틀리게 만드는 줄**을 클릭하세요.
- 정답: `count += 1` (try 밖에 있어서 건너뛴 칸도 개수에 센다)
- 부분 정답: `except Exception:` 또는 `pass` (에러를 통째로 숨긴다) → 점수는 0점이지만 "절반 맞았어요. 더 직접적인 원인이 있어요"라고 알려 주고 해설로
- 채점: 정답 줄을 고르면 1점. 한 줄만 고른다

**질문 (객관식형, 쓰지 않음 — 줄 클릭이 어려운 환경을 위한 대안으로만 남겨 둔다)**: 이 코드를 그대로 쓰면 어떤 일이 생길까요?
① 에러가 사라졌으니 문제없다
② 숫자가 아닌 칸을 건너뛰니 평균이 조금 더 정확해졌다
③ **건너뛴 칸까지 개수에 세어 평균이 실제보다 낮게 나온다. 열 이름이 바뀌어도 에러 없이 0이 나온다**
④ try를 쓰면 느려져서 큰 파일에서 문제가 된다

**실제로 돌린 결과**
| 경우 | 나와야 할 값 | 이 코드의 값 |
|---|---|---|
| 위 로그 (숫자 80, 82, 78) | 80.0 | **48.0** (240 ÷ 5칸) |
| 누가 열 이름을 `temp`에서 `Temp`로 바꾼 로그 | 에러로 알려 줘야 함 | **0.0** (에러 없이) |

**해설**
에러는 사라졌지만 문제는 사라지지 않았어요. 두 가지가 숨어 있습니다.
- `count += 1`이 `try` 밖에 있어서, 숫자로 바꾸지 못하고 건너뛴 칸도 개수에 셉니다. 평균이 80이 아니라 48이 나와요. 온도 경고 기준이 75도라면, 실제로는 넘었는데도 경고가 울리지 않습니다.
- `except Exception: pass`는 **모든 에러**를 조용히 삼킵니다. 'N/A' 같은 칸뿐 아니라, 누가 열 이름을 바꿔서 `temp` 열이 아예 없어져도 에러 없이 0을 돌려줘요. 툴이 망가졌는데 아무도 모르게 됩니다.

AI에게 "에러를 고쳐 줘"라고 하면, AI는 **에러가 안 나게** 만듭니다. **맞게** 만드는 것과는 다른 일이에요.

**더 나은 코드** (해설에 함께 보여준다)
```python
def average_temp(path):
    values = []
    with open(path, encoding="utf-8") as f:
        for row in csv.DictReader(f):
            v = row["temp"].strip()
            if v in ("", "N/A", "-"):   # 빈 값으로 정한 것만 건너뛴다
                continue
            values.append(float(v))      # 그 밖의 이상한 값은 에러로 알린다
    return sum(values) / len(values)
```
이 코드는 위 로그에서 80.0을 내고, 열 이름이 바뀌면 `KeyError`로 바로 알려 줍니다.

**마무리 문구**
> 에러가 사라졌다고 문제가 사라진 건 아닙니다. AI가 고친 코드가 "돌아가는지"가 아니라 "맞는지"를 보는 눈, SWAN에서 기릅니다.

**커리큘럼 연결**: 바이브코딩 단원의 "AI가 짠 코드 읽고 검증하기"와 "막혔을 때 빠져나오기"

### 보류: 후보 B — 결과는 맞는데, 데이터가 늘면 멈춘다

**상황**
10만 줄짜리 설비 로그에서 불량 목록(2만 개)에 있는 ID만 골라 달라고 했더니, AI가 아래 코드를 줬어요. 테스트용 작은 파일에서는 결과도 맞고 금방 끝났습니다.

```python
def find_defects(log_ids, defect_ids):
    result = []
    for i in log_ids:
        if i in defect_ids:      # defect_ids는 리스트
            result.append(i)
    return result
```

**질문**: 로그와 불량 목록이 둘 다 **10배**로 늘면, 걸리는 시간은 대략 어떻게 될까요?
① 그대로다　② 약 10배　③ **약 100배**　④ 메모리가 부족해 멈춘다

**실제로 잰 결과** (이 PC 기준)
| 로그 / 불량 목록 | 리스트로 찾기 | 집합(set)으로 찾기 |
|---|---|---|
| 1만 / 2천 | 0.19초 | 0.0007초 |
| 3만 / 6천 (3배) | 2.27초 (약 12배) | 0.004초 |

둘 다 3배가 되자 12배 느려졌다. 둘 다 10배가 되면 100배 안팎으로 느려진다.

**해설**
`i in defect_ids`는 리스트를 처음부터 끝까지 훑어 봅니다. 로그 한 줄마다 불량 목록 전체를 훑으니, 둘 다 10배가 되면 일은 100배가 돼요. `set(defect_ids)`로 한 번 바꿔 두면 찾는 데 거의 시간이 들지 않습니다. 결과는 똑같고요.

**마무리 문구**
> 작은 파일에서 맞는 코드가 큰 파일에서도 쓸 수 있는 코드는 아닙니다.

**약점**: "10배 → 100배"를 계산하는 문제라 알고리즘 지식이 있는 사람에게 유리하다. "AI 코드를 보는 눈"보다 "자료 구조를 아는가"에 가깝다.

### 보류: 후보 C — 처음 초안 (돌아가지만 다음 요구에 무너지는 구조) → 교육 중 실습 문제로 쓰기 좋다


**상황**
한 엔지니어가 AI에게 "설비 로그 CSV를 읽어서 평균 온도를 보여 주고, 기준을 넘으면 경고해 줘"라고 시켰습니다. 며칠 뒤 "압력도 해 줘"라고 하자 AI가 아래처럼 만들었어요. **두 함수 모두 문제없이 잘 돌아갑니다.**

다음 달에는 이런 요청이 들어올 예정입니다.
- 습도도 봐 줘
- 평균 말고 최댓값으로 봐 줘
- 결과를 화면(GUI)에도 띄워 줘

```python
import csv

def report_temperature(path):
    total = 0
    count = 0
    with open(path, encoding="utf-8") as f:
        for row in csv.DictReader(f):
            total += float(row["temp"])
            count += 1
    avg = total / count
    print(f"평균 온도: {avg:.1f}℃")
    if avg > 75:
        print("경고: 설비 점검 필요")

def report_pressure(path):
    total = 0
    count = 0
    with open(path, encoding="utf-8") as f:
        for row in csv.DictReader(f):
            total += float(row["pressure"])
            count += 1
    avg = total / count
    print(f"평균 압력: {avg:.1f}kPa")
    if avg > 280:
        print("경고: 설비 점검 필요")
```

**질문**: 다음 달의 요청을 생각할 때, 이 코드에서 **가장 먼저 고쳐야 할 구조 문제**는 무엇일까요?

① 변수 이름 `total`, `count`가 너무 흔해서 무엇을 세는지 알기 어렵다
② 함수마다 파일을 따로 열어서 같은 파일을 두 번 읽는다
③ **같은 일을 하는 코드가 열 이름만 바꿔 복사돼 있고, 계산과 출력(`print`)이 한 함수에 섞여 있다**
④ 데이터가 한 줄도 없으면 `count`가 0이 되어 나눗셈 에러가 난다

**해설**
네 가지 모두 틀린 말은 아니에요. 하지만 다음 달의 요청에 비춰 보면 무게가 다릅니다.
- ①은 읽기 좋게 다듬는 문제예요. 고쳐도 다음 달의 요청은 그대로 어렵습니다.
- ②는 성능 문제지만, 로그 파일이 작다면 체감하기 어려워요.
- ④는 실제로 고쳐야 할 **버그**예요. 다만 구조의 문제는 아니고, 한 줄로 고칠 수 있습니다.
- ③이 다음 달을 막는 문제예요.
  - "습도도"가 들어오면 같은 함수를 **세 번째로 복사**하게 됩니다.
  - "최댓값으로"가 들어오면 **복사된 곳을 모두** 찾아 고쳐야 해요. 하나라도 빠뜨리면 온도는 최댓값, 압력은 평균인 이상한 툴이 됩니다.
  - "화면에도"가 들어오면 계산 안에 `print`가 박혀 있어서 **계산 결과를 화면에 넘길 방법이 없어요.** 함수를 통째로 다시 짜야 합니다.

**더 나은 구조** (해설에 함께 보여준다)
```python
import csv
from statistics import mean

def read_column(path, column):
    with open(path, encoding="utf-8") as f:
        return [float(row[column]) for row in csv.DictReader(f)]

def summarize(values, how=mean):
    return how(values)

def check(value, limit):
    return value > limit
```
읽기, 계산, 판정을 나누고, 화면에 보여주는 일은 따로 둡니다. 그러면 습도는 열 이름 하나, 최댓값은 `how=max` 하나, GUI는 보여주는 쪽 하나만 바꾸면 돼요.

**마무리 문구** (결과와 상관없이 보여준다)
> 돌아가는 코드와 오래 쓸 수 있는 코드는 다릅니다. AI는 첫 번째를 잘 만들어요. 두 번째를 알아보는 눈, SWAN에서 기릅니다.

**커리큘럼 연결**: 테트리스, 2048, Bird simulator 실습에서 "기능이 늘어도 무너지지 않는 구조(MVP 아키텍처)"를 직접 겪고, 객체지향과 디자인 패턴 단원에서 이렇게 나누는 방법을 배웁니다. 바이브코딩 단원의 "구조를 지키며 키우기"에서는 AI에게 이 구조를 요구하는 법을 다룹니다.

**왜 이 문제인가**
- 문법 오류나 오타를 찾는 문제는 AI가 더 잘 찾아요. 사람에게 필요한 건 "잘 돌아가는데 무엇이 문제인가"를 보는 눈입니다
- 보기 네 개가 모두 "틀린 말은 아닌" 것이라, 무엇이 더 중요한지를 판단해야 합니다. 이게 교육이 말하는 "판단하는 눈"이에요
- 일부러 ④에 진짜 버그를 넣었어요. 버그를 고르는 사람은 "코드를 꼼꼼히 읽는 사람"이고, ③을 고르는 사람은 "앞으로를 내다보는 사람"입니다. 해설에서 둘의 차이를 보여줍니다
