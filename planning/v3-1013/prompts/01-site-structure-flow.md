## 프롬프트 1 — 사이트 구조와 흐름 전체 설계

너는 정보 구조(IA)와 사용자 흐름을 설계하는 UX 설계자야. 아래 기획 내용을 바탕으로 사내 교육 사이트 "SWAN"의 사이트 구조와 사용자 흐름을 설계해 줘. 시각 디자인(색, 글꼴)은 다루지 말고 구조와 흐름에만 집중해 줘.

### 1. 서비스 배경
- SWAN(SW Academy for Newbie)은 한 회사의 개발 파트가 운영하는 사내 SW 교육이다. 파이썬 초급 딱지를 막 뗀 현업 엔지니어가 Python 중고급과 바이브코딩(AI와 함께 코딩하는 방법)을 배운다.
- 주 1회 1시간 30분, 온라인, 3개월 과정. 수강생은 본업과 병행하며 주 3~4시간을 쓴다. 강사는 사내 사람 한 명이고, 요청하면 직접 만날 수 있다.
- 지금까지 4기를 진행했고 직전 기수는 65명이 들었다. 다음은 5기 모집이다. 선발은 없고 신청하면 모두 수강한다.
- 이 사이트는 교육과 운영 파트를 알리고, 교육 신청을 받는다.
- 사내망의 PC에서만 쓴다. 모바일은 지원하지 않는다. 들어오면 사내 통합 로그인(SSO)으로 자동 로그인된다.

### 2. 풀어야 할 문제
- 지금은 모집 공지가 글로 된 메일뿐이다. 받은 사람은 "내 수준에 맞나, 듣고 나면 무엇을 만들 수 있나"를 알 수 없어서 "다음 기수에 듣지 뭐" 하고 닫는다.
- 대상자의 가장 큰 어려움: **AI가 코드를 짜 줘도, 그 코드가 맞는지 판단할 눈이 없다.** AI에게 에러를 붙여넣고 다시 받기를 반복하고, 한 부분에서 막혀도 물어볼 사람이 없다.
- 기존 교육은 온라인이거나 사외에서 열리고, 강사가 사내 환경을 모른다.
- 그래서 이 사이트는 글이 아니라 **눈으로 보는 증거**로 설득한다: 졸업생이 만든 완성작, 실제 커리큘럼, 내 수준을 재 보는 테스트, 그리고 이 사이트 자체를 바이브코딩으로 만들었다는 사실.

### 3. 사용자 유형과 권한
| 유형 | 어떤 사람 | 할 수 있는 것 |
|---|---|---|
| 로그인 실패 | 자동 로그인이 실패한 방문자 | 모든 화면 보기만. 버튼을 누르면 "로그인이 필요해요" |
| 직원 | 로그인된 사내 직원 누구나 | 신청·취소, 수준 테스트, 완성작 좋아요, 아이디어 남기기·공감, 다음 기수 알림 받기 |
| 수강생 | 현재 기수 신청자 | 직원 권한 + 토이프로젝트 글쓰기·참여 |
| 졸업생 | 역대 수료생 명단에 있는 사람 | 직원 권한 + 완성작 올리기·수정, 토이프로젝트 글쓰기·참여 |
| 관리자 | 운영자와 부장 (추가될 수 있음) | 모든 권한 + 관리자 화면 |

대표 인물
- 예비 수강생: 공정 기술 부서 엔지니어. 파이썬으로 데이터 정리 스크립트는 짜 봤고, AI로 툴을 만들어 보려다 막힌 적이 있다. 업무 중에 메일의 [신청하기]를 눌러 들어온다.
- 졸업생: 4기 수료. 부서에서 쓰는 분석 툴을 만들었고, 그걸 자랑하고 싶다.
- 실무진: 교육을 들을 시간은 없지만 "이런 툴 있으면 좋겠다"는 생각이 많다. 부서장을 거치는 공식 요청은 부담스럽다.
- 팀장: 팀원을 교육에 보낼지 판단한다. 보기만 한다.

### 4. 핵심 행동
- 단 하나의 핵심 행동은 **교육 신청**이다. ① 완성작과 커리큘럼을 확인한다 → ② 수준 테스트로 내 수준을 재 본다(선택) → ③ 신청서를 제출한다.
- 주 행동 버튼은 어느 화면에서든 상단 오른쪽에 하나만 있다. 상태에 따라 [신청하기] / [신청 완료] / [다음 기수 알림 받기]로 바뀐다.

### 5. 화면 목록 (이번 범위)
| 화면 | 역할 | 들어가는 내용 |
|---|---|---|
| 홈 | 스크롤만으로 이해하고 신청까지 가게 한다 | 아래 10개 섹션 |
| 완성작 갤러리 | 졸업생 완성작을 구경한다 | 기수·부서 필터, 정렬, 카드(대표 이미지, 좋아요 수, 마우스를 올리면 짧은 설명) |
| 완성작 상세 | 한 작품을 깊이 본다 | 대표 이미지, 만든 사람(이름·부서·기수), 문제, 효과, 화면 캡처, 발표자료, 자세한 설명, 저장소 주소, 좋아요 |
| 완성작 올리기 | 졸업생이 완성작을 등록한다 | 민감 정보 안내, 입력 폼, 확인 체크 |

| 토이프로젝트 | 수강생과 졸업생이 팀원을 모은다 | 모집 글 목록, 글쓰기, 글 상세, 참여하고 싶어요 |
| 아이디어 보드 | 직원 누구나 가벼운 개발 요청을 남긴다 | 아이디어 카드, 남기기, 공감, 상태, 파트 답변 |
| 제작 과정 | 이 사이트를 어떻게 만들었는지 공개한다 | 제작 타임라인, 실제 프롬프트, 막혔던 순간과 해결 |
| 관리자 | 운영한다 | 기수 / 신청자 / 졸업생 / 완성작 검수 / 토이프로젝트 / 아이디어 / 수준 테스트 / 커리큘럼 / 관리자 |

홈의 섹션 순서 (확정, 바꾸지 말 것)
1. 영상 인트로와 메인 문구
2. 한 줄 소개, 핵심 3가지, 모집 상태
3. 숫자(기수, 누적 수료생, 참여 부서)와 졸업생 이름이 흐르는 띠, 부서 이름이 흐르는 띠
4. 완성작 미리보기
5. 강사 소개
6. 커리큘럼 (배우는 흐름 4단계 — 다지기, 깊어지기, 만들기, AI와 함께 만들기 — 단원별 상세, 실습 프로젝트 11개 모음과 미리보기, 교육 목표, 수강 안내, 모집 대상)
7. 수준 테스트 안내
8. 파트 소개
9. 아이디어 보드 미리보기
10. 마지막 신청 안내, 제작 과정으로 가는 연결

### 6. 반드시 반영할 규칙
진입
- 유일한 진입 경로는 모집 메일과 사내 게시판의 [신청하기] 링크다. 이 링크는 신청 화면이 아니라 **홈 첫 화면 맨 위**로 간다. 누구나 홍보 내용을 거치게 하기 위해서다.
- 들어오면 자동으로 로그인된다. 로그인 버튼이나 로그인 화면이 없다. 로그인이 실패해도 모든 화면을 볼 수 있다.

신청
- 선발이 없다. 신청하면 수강 확정이다.
- 신청서는 두 칸뿐이다: 파이썬을 써 본 경험(세 가지 중 고르기), 만들고 싶은 것(선택). 이름·부서·사번은 화면에 보여주지 않는다.
- 한 사람은 한 기수에 유효한 신청이 한 건뿐이다.
- 이미 신청한 사람에게는 주 행동 버튼이 [신청 완료]로 보이고, 누르면 "신청을 취소할까요?"라고 묻는다. 취소하면 다시 신청할 수 있다.
- 모집 중인 기수는 최대 하나다. 모집 기간이 아니면 주 행동 버튼이 [다음 기수 알림 받기]가 된다.

수준 테스트
- 선택 사항이다. 신청의 조건이 아니다.
- 문제는 6개. 1~4번은 보기 고르기, 5번은 주관식(실행 결과를 직접 적기), 6번은 "에러를 고쳐 달라고 했더니 AI가 에러를 숨긴 코드"에서 결과를 틀리게 만드는 줄을 직접 클릭해 고르기다.
- 결과는 합격·불합격이 아니라 성장 단계 셋 중 하나다(알에서 나온 오리 / 아기 오리 / 어린 백조). **어떤 결과가 나와도 신청을 막지 않는다.** 가장 낮은 단계에는 기초 자료와 [다음 기수 알림 받기]를 권하되 신청도 열어 둔다.
- 다시 풀 수 있지만 첫 결과가 기준 기록으로 남는다. 결과는 개인별로 저장되고 관리자가 본다. 시작 화면에서 기록된다는 사실을 알린다.

완성작
- 졸업생만 올린다. 올리기 전에 민감한 내용을 가리라는 안내를 보여주고 확인 체크를 받는다.
- 관리자가 승인해야 공개된다. 상태는 승인 대기 → 공개 / 반려(이유 포함)다. 반려되면 고쳐서 다시 올린다. 공개된 것을 수정하면 다시 승인 대기가 된다.
- 만든 사람의 이름, 부서, 기수를 모두 표시한다.
- 좋아요는 로그인한 사람만, 한 사람이 한 번이다.

아이디어 보드
- 사내 모든 직원이 남긴다. 올리면 바로 공개되고, 관리자가 숨길 수 있다.
- 쓰는 사람이 이름 표시 방식을 고른다(이름과 부서 / 부서만). 관리자는 어느 쪽이든 누가 썼는지 안다.
- 공감은 한 사람이 한 번이다.
- 상태: 접수됨 → 검토 중 → 만드는 중 → 완료 / 보류. 관리자가 바꾸고 한 줄 답변을 단다.

토이프로젝트
- 누구나 볼 수 있지만 글쓰기와 참여는 수강생과 졸업생만 한다. 올리면 바로 공개되고, 관리자가 숨길 수 있다.
- [참여하고 싶어요]를 누르면 글쓴이에게 이름과 부서가 전달된다. 참여 희망자 목록은 글쓴이만 본다. 글쓴이가 모집을 마감한다.

관리자
- 기수가 끝나면 신청자를 "수료 처리"해서 졸업생으로 만든다. 역대 졸업생 명단은 엑셀로 올린다.
- 신청자 명단을 엑셀로 내려받는다.

범위 밖 (화면을 만들지 말 것)
- 통계 화면, 완성작 댓글, 메일·메신저 알림 발송, 모바일 화면, 회원 가입·로그인 화면, 마이페이지

### 7. 만들어 줄 결과물
A. **사이트맵** — 계층, 주소, 화면별 접근 권한. mermaid로도 그려 줘.
B. **내비게이션 설계** — 상단 메뉴 항목, 사용자 유형별로 달라지는 메뉴, 주 행동 버튼의 상태별 변화 표.
C. **화면별 구조** — 화면마다 블록 순서, 각 블록의 목적, 누르면 가는 다음 화면. 빈 상태, 불러오는 중, 오류 상태도 함께.
D. **사용자 흐름도** — 아래 각각을 mermaid flowchart로. 시작 계기, 결정 지점, 끝 화면이 보이게.
  1. 예비 수강생: 메일 → 홈 → 신청 완료 (수준 테스트를 푸는 경우와 건너뛰는 경우)
  2. 이미 신청한 사람이 다시 들어와 취소하는 경우
  3. 모집 기간이 아닐 때 들어온 사람
  4. 로그인이 실패한 방문자가 신청·좋아요를 누른 경우
  5. 수준 테스트에서 가장 낮은 결과를 받은 사람
  6. 졸업생: 완성작 올리기 → 반려 → 고쳐서 다시 올리기 → 공개
  7. 실무진: 아이디어 남기기 → 상태 변화를 확인하기
  8. 수강생·졸업생: 토이프로젝트 모집 글 쓰기와 참여
  9. 관리자: 신청자 확인과 내려받기, 완성작 승인, 아이디어 처리, 수료 처리
E. **상태 전이도** — 신청, 완성작, 아이디어, 토이프로젝트 모집 글, 기수(모집 상태)를 각각 mermaid stateDiagram으로.
F. **권한 표** — 기능 × 사용자 유형. 권한 없는 사람이 주소로 직접 들어왔을 때의 처리도 함께.
G. **빠진 곳과 질문** — 위 규칙만으로 정할 수 없던 부분, 권장안과 이유. 임의로 정한 것은 "가정"이라고 표시해 줘.

### 8. 설계 원칙
- 가장 짧아야 하는 길은 "홈 → 신청 완료"다. 신청서 제출까지 누르는 횟수를 최소로 한다.
- 홈의 섹션 순서는 증거를 먼저 보여주는 순서다(숫자 → 완성작 → 강사 → 커리큘럼). 바꾸지 않는다.
- 주 행동 버튼은 화면마다 하나만 강조한다.
- 고르는 방식을 우선하고 타이핑은 최소로 한다. 되돌릴 수 없는 일은 한 번 더 묻는다.
- 기획에 없는 화면이나 기능을 더하지 않는다. 필요해 보이면 G에 질문으로 적는다.
- 화면 문구는 한국어로 쓴다.

## 프롬프트 2 — 홈 구체화

홈의 10개 섹션을 스크롤 구간별 표로 구체화해 줘. 섹션마다 아래를 적어 줘.
- 방문자가 이 구간에서 품는 질문 (예: "많은 사람이 들었나?", "내 수준에 맞나?")
- 화면에 보이는 것 (글, 숫자, 카드, 그림 자리)
- 누를 수 있는 것과 누르면 가는 곳
- 다음 섹션으로 넘어가게 만드는 요소
- 이 섹션에서 떠나는 사람을 줄이려면 무엇이 필요한지

그리고 1440×900 화면에서 첫 화면(스크롤 전)에 무엇이 보여야 하는지, 주 행동 버튼이 섹션마다 어떻게 보이는지도 정리해 줘.

## 프롬프트 3 — 예외 흐름 점검

아래 막히는 경우마다 보여줄 화면, 문구, 돌아갈 곳을 정해 줘.
1. 수준 테스트를 풀다가 중간에 창을 닫고 나중에 다시 들어온 경우
2. 신청서를 내려는 순간 관리자가 모집을 닫은 경우
3. 졸업생 명단에 없는데 본인은 졸업생이라고 생각해서 [완성작 올리기]를 찾는 경우
4. 완성작이 반려됐는데 이유를 이해하지 못한 경우
5. 자기가 올린 아이디어가 관리자에게 숨김 처리된 경우
6. 토이프로젝트 모집 글에 참여를 눌렀는데 글쓴이가 모집을 마감한 경우
7. 자동 로그인은 됐지만 부서 정보가 비어 있는 경우
8. 신청을 취소한 사람이 모집 마감 뒤에 다시 신청하려는 경우

## 프롬프트 4 — 관리자 화면 구체화

관리자 화면의 9개 메뉴를 구체화해 줘. 메뉴마다 아래를 적어 줘.
- 목록의 열, 기본 정렬, 필터
- 한 줄에서 할 수 있는 동작과 여러 줄을 골라 한 번에 하는 동작
- 되돌릴 수 없는 동작(수료 처리, 삭제, 관리자 해제)의 확인 절차
- 엑셀 올리기(졸업생 명단)의 단계: 파일 고르기 → 미리보기와 건수 → 오류가 있는 줄 표시 → 확인
- 부장은 주로 보기와 상태 변경만 한다. 그 사용에 맞게 가장 자주 쓰는 동작이 무엇인지와 화면 배치를 제안해 줘
- 승인 대기 완성작이나 새 아이디어가 있다는 것을 관리자가 어떻게 알아채는지
