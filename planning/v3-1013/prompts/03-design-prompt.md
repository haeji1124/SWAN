# 디자인 프롬프트 — SWAN 웹사이트 시안

기준: 2026-10-14 기획(v3). PC 전용(1440폭). 디자인 방향은 세 개를 비교해 고른다. 이전 시안은 "너무 AI 틱하다"는 평가를 받았으므로, 그 느낌을 피하는 것이 이번 시안의 첫 번째 조건이다.

사용법
1. Claude Design에서 새 디자인을 열고 아래 "첨부할 파일" 일곱 장을 올린다. 모두 `SWAN/design/images/`에 모아 두었다.
2. **프롬프트 1**로 세 방향의 첫 화면을 받아 비교하고 하나를 고른다. 마음에 드는 게 없으면 프롬프트 5~7로 다듬거나, 두 방향을 섞어 달라고 한다.
3. 방향을 고른 뒤 **프롬프트 2**(디자인 기준과 홈 전체) → **프롬프트 3**(나머지 화면) → **프롬프트 4**(상태별 화면) 순서로 진행한다. 이때 고른 방향에 필요한 그림(성장 단계, 강사 캐릭터, 빈 상태 등)을 `02-image-prompts-higgsfield.md`의 2부로 더 만든다.
4. **프롬프트 8**로 구현 전달용 정리를 받는다.
5. 시안 화면과 정리 문서를 `SWAN/design/`에 저장한다. 구현 프롬프트의 Phase 7에서 쓴다.

## 프롬프트 1 — 세 방향의 첫 화면 비교

사내 교육 사이트의 첫 화면을 **서로 완전히 다른 세 가지 디자인 방향**으로 만들어 줘. 세 개를 나란히 놓고 비교해서 하나를 고를 거야. 화면 폭은 1440이고 PC 전용이야. 각 방향마다 "첫 화면(스크롤 전)"과 "바로 아래 한 섹션"까지만 만들어 줘.

**이 사이트가 하는 일**
- SWAN(SW Academy for Newbie)은 한 회사의 개발 파트가 운영하는 사내 SW 교육이야. 파이썬 초급 딱지를 막 뗀 현업 엔지니어가 Python 중고급과 바이브코딩(AI와 함께 코딩하는 방법)을 배워. 주 1회 온라인, 3개월 과정이야.
- 들어오는 사람은 업무 중에 모집 메일의 [신청하기]를 누른 엔지니어야. 파이썬은 쓸 줄 알지만, AI가 짜 준 코드가 맞는지 판단할 눈이 없어서 답답해하는 사람이지. "내 수준에 맞나, 듣고 나면 뭘 만들 수 있나"가 궁금해.
- 이 사이트는 글이 아니라 눈으로 보는 증거(졸업생의 완성작, 실제 커리큘럼, 수준 테스트)로 설득해. 그리고 **이 사이트 자체를 AI와 함께 만들었다는 것을 공개**해.

**가장 중요한 조건: "AI가 만든 것처럼 보이지 않게"**
이전 시안은 "너무 AI 틱하다"는 이유로 버려졌어. 이 사이트는 AI로 만들었다는 걸 숨기지 않지만, 사람의 취향과 판단이 보여야 해. 그게 "코드를 판단하는 눈"이라는 교육 메시지의 증거가 되거든. 세 방향 모두 아래를 지켜 줘.
- 그라디언트, 빛 번짐, 반투명 유리 카드를 쓰지 않는다
- 어두운 바탕에 보라·파랑 빛을 쓰지 않는다
- 똑같은 크기의 카드를 세 개 나란히 놓는 구성을 쓰지 않는다
- 모든 것을 가운데 정렬하지 않는다. 왼쪽 정렬과 비대칭 배치를 쓴다
- 제목 위에 작은 영어 대문자 라벨을 습관처럼 붙이지 않는다
- 이모지를 아이콘으로 쓰지 않는다
- 색은 바탕색, 글자색, 강조색 하나로 제한한다
- 글자의 크기 차이와 여백으로 위계를 만든다

**첫 화면에 들어갈 내용 (세 방향 모두 같음)**
- 상단 메뉴: 로고 SWAN · 완성작 · 커리큘럼 · 수준 테스트 · 토이프로젝트 · 아이디어 보드 · 오른쪽 끝 [신청하기] 버튼
- 메인 문구: **날개는 AI가 달아 줍니다. 나는 법은 여기서 배웁니다.**
- 서브 문구 (임시): AI 시대, SW를 보는 눈을 기릅니다.
- 정보 한 줄: Python 중고급 · 바이브코딩 · 주 1회 온라인 3개월 · 5기 모집 중 D-7 (가상)
- 캐릭터 그림 (첨부한 것)
- 바로 아래 섹션: 숫자 세 개 — 4개 기수, 수료생 187명 (가상), 참여 부서 12곳 (가상) — 와 졸업생 이름이 가로로 흐르는 띠 (가상 이름: 김도윤, 이서아, 박지호, 최하린, 정민준, 강유나, 윤시우, 임채원 …)

**세 방향**

**A. 개발자의 노트**
- 느낌: 프로그래머가 여백에 그림을 그려 가며 쓴 노트. 따뜻한 미색 종이 바탕, 굵고 큰 글자, 넉넉한 여백
- 색: 바탕 미색 `#f6f1e7`, 글자 짙은 남색 `#1b2233`, 강조 노랑 `#f2b824`
- 글꼴: 제목은 굵은 고딕, 본문은 읽기 편한 고딕, 숫자와 작은 표시는 고정폭 글꼴. 코드 편집기의 줄 번호나 주석 표시(`//`, `#`)를 장식으로 써도 좋아
- 캐릭터와 그림: 첨부한 `a-character-sheet.png`, `a-hero-scene.png`. 납작한 손그림을 스티커처럼 붙인 느낌. 첫 화면에는 `a-hero-scene.png`를 쓰고 왼쪽 빈 종이에 메인 문구를 올린다
- 모서리는 거의 직각, 그림자 대신 가는 선

**B. 밝은 물가**
- 느낌: 맑은 날의 호숫가. 밝고 친근하고 가벼움
- 색: 바탕 흰색 `#ffffff`와 옅은 하늘색 `#d6ecfb`, 글자 짙은 남색 `#16263d`, 강조 오리 노랑 `#f6c33c`
- 글꼴: 둥근 느낌의 고딕
- 캐릭터와 그림: 첨부한 `b-character-sheet.png`, `b-hero-scene.png`, `b-stickers.png`. 첫 화면에는 `b-hero-scene.png`를 쓰고 왼쪽 빈 하늘에 메인 문구를 올린다
- 모서리는 넉넉하게 둥글고, 그림자는 아주 옅게

**C. 달빛 호수, 다시**
- 느낌: 영화 포스터. 화면 가득한 그림 한 장과 큰 글자. 조용하고 묵직함
- 색: 바탕 짙은 남색 `#0b1424`, 글자 달빛 크림 `#f3ead2`, 강조 호박색 `#e8b36a`
- 글꼴: 제목은 명조, 본문은 고딕
- 캐릭터와 그림: 첨부한 `c-hero-scene.png`를 화면 전체에 쓴다. `c-character.png`는 아래 섹션에서 쓴다
- 카드나 상자를 거의 쓰지 않고, 그림 위에 글자를 직접 올린다. 빛나는 테두리와 시안색 빛을 쓰지 않는다

**만들어 줄 것**
1. 세 방향의 첫 화면을 각각 한 화면으로
2. 방향마다 한 줄 설명: 이 방향의 장점, 약점, 어울리는 인상
3. 세 방향을 나란히 놓은 비교 화면
4. 네 생각에 "AI가 만든 것처럼 보이지 않게"라는 조건에 가장 잘 맞는 방향과 그 이유

더 나은 색이나 글꼴 조합이 있으면 이유와 함께 제안해 줘.

## 프롬프트 2 — 디자인 기준과 홈 전체 (방향을 고른 뒤)

{고른 방향}으로 가기로 했어. 이 방향의 디자인 기준을 정리하고, 홈 화면 전체를 만들어 줘. 화면 폭 1440, PC 전용.

**만들 것 1: 디자인 기준 한 장**
- 색: 바탕, 글자, 강조, 선, 그리고 성공·주의·오류를 알리는 색. 각각 값과 쓰이는 곳
- 글자 단계: 가장 큰 제목부터 작은 설명까지 크기, 굵기, 줄 간격
- 버튼: 주 행동 버튼, 보조 버튼, 글자만 있는 버튼. 각각 기본, 마우스를 올렸을 때, 눌렀을 때, 쓸 수 없을 때
- 카드, 배지(상태 표시), 입력 칸, 고르기 버튼, 체크 칸, 확인 창, 화면 구석의 짧은 확인 메시지
- 모서리, 선 굵기, 여백 단위

**만들 것 2: 홈 화면 전체 (위에서 아래로 10개 섹션, 이 순서를 지킨다)**

섹션마다 구성을 다르게 해 줘. 같은 모양의 카드 줄이 두 번 나오지 않게.

1. **인트로**: 화면 전체 높이. 영상이 들어갈 자리(지금은 정지 그림). 메인 문구 "날개는 AI가 달아 줍니다. 나는 법은 여기서 배웁니다." 아래로 스크롤하라는 표시
2. **한 줄 소개**: "AI 시대, SW를 보는 눈을 기릅니다." (임시) + 핵심 세 가지 — 사내 환경을 아는 사내 강사가 가르칩니다 / 주 1회 온라인, 3개월, 주 3~4시간이면 됩니다 / 끝나도 물어볼 사람이 남습니다 + "5기 모집 중, 마감 D-7" (가상) + [신청하기]
3. **숫자와 띠**: 4개 기수 · 수료생 187명 (가상) · 참여 부서 12곳 (가상). 그 아래 졸업생 이름이 가로로 흐르는 띠와, 부서 이름이 반대 방향으로 흐르는 띠 (부서 이름은 "공정기술 1팀", "설비기술팀", "품질보증팀" 같은 가상 이름으로)
4. **완성작 미리보기**: 제목 "졸업생이 만든 것들". 카드 5개 — 대표 그림과 좋아요 수가 보이고, 마우스를 올리면 짧은 설명이 나타난다. 올렸을 때의 모습도 한 장 보여 줘. 예시 (가상): "설비 로그 자동 요약기 · 4기 · 좋아요 23 · 매일 30분 걸리던 로그 확인을 2분으로", "주간 보고서 생성기 · 3기 · 좋아요 17", "불량 이미지 분류 도우미 · 4기 · 좋아요 31". [완성작 전체 보기]
5. **강사 소개**: 강사는 한 명이고 캐릭터 그림으로 표현한다. 이름 (가상: 한 부장), 하는 일, 한마디 "코드는 AI가 짜도, 맞는지는 여러분이 봐야 합니다." (임시), "요청하면 직접 만날 수 있어요"
6. **커리큘럼**: 실제 과정은 이론 5단원과 실습 프로젝트 11개로 이뤄져 있다. 두 부분으로 보여 줘.
   - **배우는 흐름 4단계**: ① 다지기 — 파이썬 환경 구성(윈도우), 함수 활용법(map/reduce) ② 깊어지기 — 파이썬 고급 개념(class, closure, decorator, generator, coroutine), 알고리즘 기초(재귀 함수), 객체지향과 디자인 패턴(Strategy, Command, Observer 등) ③ 만들기 — 실습 프로젝트 ④ AI와 함께 만들기 ("5기 신설" 표시) — 만들 것을 정하기, AI에게 제대로 시키기, AI가 짠 코드 읽고 검증하기, 막혔을 때 빠져나오기, 구조를 지키며 키우기, 회사에서 안전하게 쓰기. 네 번째 단계가 앞의 세 단계 위에 쌓인다는 느낌이 들게 해 줘. 단원 하나가 펼쳐진 모습을 보여 줘
   - **실습 프로젝트 모음** (이 섹션에서 가장 크게): "모든 실습은 무엇을 만들지 미리 보여 드려요". 프로젝트 카드 11개 — 미리보기 그림이나 영상 자리, 제목, 한 줄 설명. 주제로 걸러 보는 버튼(재귀와 파싱 / 탐색 알고리즘 / 아키텍처 / 객체지향·함수형 / 수학과 시각화 / 우리 업무와 닿는 과제). 카드 하나가 펼쳐진 모습도 보여 줘
     - Fourier Series로 도형 그리기 — 회전하는 화살표들이 그림을 그려 내는 애니메이션
     - 테트리스 — 녹화와 리플레이까지, 구조를 잡으며 만든다
     - Equation parser — 괄호가 있는 수식을 읽고 계산한다
     - 미로찾기 solver — 최단 경로를 찾아 화면에 그린다
     - Eight puzzle solver — 가장 적은 움직임으로 퍼즐을 푼다
     - Bird simulator — 새 떼의 움직임을 계산한다
     - 2048 게임 — 규칙과 데이터 구조를 직접 짠다
     - 8마디 작곡 — 규칙에 따라 음악을 자동으로 만든다
     - HW 자동 생성 — 숫자 하나를 넣으면 회로 설계 파일이 나온다
     - 게이트 레벨 시뮬레이터 — 논리 회로의 신호를 시간에 따라 계산한다
     - Parametric tree — 재귀로 3D 나무를 그린다
   - 프로젝트 카드는 크기를 다르게 섞어서, 똑같은 카드 줄이 되지 않게 해 줘. 완성작 미리보기 섹션과 구성이 겹치지 않게
   - 옆이나 아래에 교육 목표 세 가지(부서에 필요한 SW를 직접 만든다 / 실습으로 만드는 힘을 기른다 / 다시 쓸 수 있는 코드를 짠다), 수강 안내(목·금 중 주 1회 1시간 30분, 온라인), "이런 분께 맞아요" 세 가지
7. **수준 테스트 안내**: "3분이면 내 수준을 알 수 있어요". 성장 단계 그림 세 개(알에서 나온 오리, 아기 오리, 어린 백조). [테스트 시작하기]
8. **파트 소개**: 이 교육을 운영하는 개발 파트 소개. "현업에 필요한 웹과 툴을 만듭니다". 만든 것 세 가지 (가상). [아이디어 남기기]
9. **아이디어 보드 미리보기**: "부서장님께 말하긴 애매한 작은 불편, 여기 남겨 주세요". 공감 많은 아이디어 세 개 (가상: "설비 점검표를 사진으로 찍으면 표로 바꿔 주는 툴 · 공감 14 · 검토 중"). [아이디어 보드 보기]
10. **마지막 신청 안내**: 마무리 문구, 모집 마감일, [신청하기]. 맨 아래에 "이 사이트는 바이브코딩으로 만들었습니다 →"

**지킬 것**
- 프롬프트 1의 "AI가 만든 것처럼 보이지 않게" 조건을 모두 지킨다
- 주 행동 버튼 [신청하기]는 상단 오른쪽에 항상 있고, 화면마다 가장 눈에 띄는 버튼은 하나뿐이다
- 스크롤할 때 무엇이 움직이는지 화면 옆에 주석으로 적어 줘 (섹션 등장, 숫자가 세어 올라감, 띠가 흐름 등)
- 문구는 한국어

## 프롬프트 3 — 나머지 화면

같은 디자인 기준으로 나머지 화면을 만들어 줘. 신청, 수준 테스트, 관리자처럼 정보를 읽고 입력하는 화면은 장식 없이 깔끔하게 둬.

1. **완성작 갤러리**: 제목과 완성작 수 → 기수·부서 필터, 정렬(최신순·좋아요순) → 카드 그리드 9개 (가상). 졸업생에게만 보이는 [완성작 올리기]
2. **완성작 상세**: 대표 그림 → 제목, 만든 사람(이름·부서·기수), 좋아요 버튼 → 무슨 문제를 풀었나 → 효과 "매일 30분 → 2분" (가상) → 화면 캡처 세 장 → 발표자료 보기 → 자세한 설명 → 저장소 주소 → "나도 이런 걸 만들고 싶다면" [신청하기] → 같은 부서·같은 기수의 다른 완성작
3. **완성작 올리기**: 맨 위에 안내 상자 "올리기 전에 확인해 주세요 — 등록한 완성작은 관리자 승인을 거쳐 사내 모든 임직원에게 공개됩니다. 화면 캡처나 설명에 민감한 내용이 보이면 지우거나 가린 뒤 올려 주세요." → 입력 칸(제목, 짧은 설명, 대표 그림, 무슨 문제를 풀었나, 효과, 화면 캡처, 발표자료, 저장소 주소, 자세한 설명) → "민감한 내용이 없는지 확인했습니다" 체크 → [올리기]. 필수와 선택이 한눈에 구분되게
4. **수준 테스트**: 여섯 장 — ① 시작 화면("3분이면 내 수준을 알 수 있어요", 문제 6개, "결과는 교육 운영에 참고하기 위해 기록됩니다. 신청한 분은 모두 수강할 수 있으니 편하게 풀어 보세요.") ② 보기 고르기 문제(진행 표시 2/6, 파이썬 코드 5줄, 질문, 보기 4개) ③ 주관식 문제(진행 표시 5/6, 재귀 함수 코드 5줄, "출력되는 그대로 적어 주세요", 입력 칸 하나) ④ 마지막 문제(진행 표시 6/6. 위에서 아래로: "에러를 붙여넣고 고쳐 달라고 했더니 AI가 이렇게 고쳤어요. 이제 에러 없이 숫자가 나옵니다" → 원래 에러 `ValueError: could not convert string to float: 'N/A'` → 로그 파일 다섯 줄 → 줄 번호가 있는 코드 12줄 → "결과를 틀리게 만드는 줄을 클릭하세요". `count += 1` 줄을 고른 상태) ⑤ 결과(성장 단계 그림 "아기 오리", "기초는 있어요. 복습 시간을 조금 더 잡으면 충분히 따라올 수 있어요.", 6개 중 4개, [신청하기], 접혀 있는 해설) ⑥ 6번 해설(코드 위에 고른 줄과 정답 줄을 색으로 표시, "나와야 할 값 80.0 / 이 코드의 값 48.0" 표, 더 나은 코드, 마무리 문구 "에러가 사라졌다고 문제가 사라진 건 아닙니다")
   - 코드 화면은 고정폭 글꼴과 줄 번호. 6번의 줄은 마우스를 올리면 옅게 칠해지고, 누르면 고른 줄로 표시된다
5. **신청**: 두 장 — ① 기수 정보(5기, 모집 기간, 개강일, 목요일 오후 4시 (가상), "주 3~4시간이 필요해요")와 두 칸짜리 신청서(파이썬을 써 본 경험: 거의 없음 / 간단한 스크립트 / 업무에 꾸준히 사용, 만들고 싶은 것(선택)) ② 접수 완료("5기 신청이 접수됐어요", 이름과 부서, 신청 일시, 개강까지 남은 날, 축하하는 캐릭터 그림, [완성작 구경하기])
6. **아이디어 보드**: 정렬(공감순·최신순) → 아이디어 카드 6개 (제목, 설명, 올린 사람, 공감 수, 상태 배지, 파트 답변이 달린 것 두 개) → [아이디어 남기기]를 누르면 나오는 작은 입력 창(제목, 설명, 이름 표시 방식: 이름과 부서 / 부서만)
7. **토이프로젝트**: 모집 글 목록(제목, 만들 것, 필요한 인원, 모집 중/마감) → 글 상세([참여하고 싶어요]) → 글쓴이에게만 보이는 참여 희망자 목록
8. **제작 과정**: 머리말 "이 사이트는 바이브코딩으로 만들었습니다" → 숫자로 보는 제작 → 제작 타임라인(기획 → 화면 구조 → 디자인 → 구현 → 다듬기) → 실제로 쓴 프롬프트("이렇게 시켰더니"와 "이게 나왔다"를 나란히, 접힌 긴 프롬프트와 [펼쳐 보기], [복사하기]) → **막혔던 순간과 해결**(가장 눈에 띄게: AI가 틀린 결과를 냈을 때 무엇을 보고 어떻게 고쳤는지 세 가지 사례 (가상)) → "이 방법을 SWAN의 'AI와 함께 만들기' 단원에서 다룹니다" → [신청하기]
9. **관리자**: 왼쪽 메뉴(기수 / 신청자 / 졸업생 / 완성작 검수 / 토이프로젝트 / 아이디어 / 수준 테스트 / 커리큘럼 / 관리자), 오른쪽 내용. 두 장 — ① 신청자 목록 표(이름, 부서, 신청 일시, 파이썬 경험, 만들고 싶은 것, 수준 테스트 결과)와 [엑셀로 내려받기] ② 완성작 검수(승인 대기 목록과 미리보기, [승인], [반려])

## 프롬프트 4 — 상태별 화면

같은 화면이 상황에 따라 달라지는 모습을 만들어 줘.

1. **주 행동 버튼의 세 가지 상태**: [신청하기] / [신청 완료] / [다음 기수 알림 받기]. 그리고 [신청 완료]를 눌렀을 때 나오는 "신청을 취소할까요?" 확인 창
2. **로그인이 실패한 방문자**: 화면은 다 보이지만 [신청하기]나 좋아요를 누르면 나오는 "로그인이 필요해요" 안내
3. **모집 기간이 아닐 때의 홈**: 섹션 2의 모집 상태가 "지금은 모집 기간이 아니에요"로 바뀌고 버튼이 [다음 기수 알림 받기]인 모습
4. **수준 테스트 결과 세 가지**: 어린 백조("지금 딱 SWAN이 필요한 단계예요. 고급까지 함께 가요."), 아기 오리, 알에서 나온 오리("지금은 기초를 먼저 다지는 걸 추천해요." + 추천 기초 자료 세 개 + [다음 기수 알림 받기] + [그래도 신청하기])
5. **완성작의 상태**: 내 완성작 목록에서 "승인 대기 중", "공개됨", "반려됨(이유 보기)"
6. **빈 상태**: 완성작이 하나도 없을 때("곧 졸업생들의 작품이 걸립니다"), 아이디어가 하나도 없을 때, 토이프로젝트 모집 글이 없을 때. 캐릭터 그림을 쓴다
7. **오류와 권한 없음**: 불러오지 못했을 때, 졸업생이 아닌 사람이 완성작 올리기에 들어왔을 때, 관리자가 아닌 사람이 관리자 화면에 들어왔을 때
8. **짧은 확인 메시지**: "신청이 접수됐어요", "좋아요를 눌렀어요", "아이디어를 남겼어요", "저장됐어요"

## 프롬프트 5 — 더 과감하게 (시안이 얌전할 때)

지금 시안이 너무 얌전하고 평범해. 더 과감하게 만들어 줘.
- 메인 문구를 화면 폭의 절반 이상을 차지할 만큼 크게
- 섹션마다 구성이 확실히 다르게: 어떤 섹션은 글자만, 어떤 섹션은 그림이 화면을 가득, 어떤 섹션은 좌우로 크게 나뉘게
- 흐르는 띠(졸업생 이름, 부서)를 훨씬 크고 굵게
- 캐릭터가 섹션의 경계를 넘나들게 (한 섹션의 아래에서 다음 섹션의 위로 걸치게)
- 단, 그라디언트와 빛 번짐, 반투명 유리 카드는 여전히 쓰지 않는다

## 프롬프트 6 — 더 차분하게 (시안이 과할 때)

지금 시안이 너무 요란해. 내용이 먼저 읽히게 차분하게 만들어 줘.
- 한 화면에 강조하는 것을 하나로 줄인다
- 색을 쓰는 곳을 주 행동 버튼과 숫자 정도로 줄인다
- 여백을 늘리고 장식을 덜어 낸다
- 움직이는 요소는 흐르는 띠 하나만 남긴다

## 프롬프트 7 — 특정 섹션만 시안 세 개

{섹션 이름} 섹션만 서로 다른 구성의 시안 세 개로 보여 줘. 디자인 기준은 그대로 두고 배치와 표현 방식만 바꿔 줘.
(예: 커리큘럼을 세로 타임라인 / 가로로 넘기는 단계 / 물 위의 징검돌 그림으로. 완성작 미리보기를 한 줄 카드 / 크기가 다른 카드의 모자이크 / 한 작품씩 크게 넘기는 방식으로.)

## 프롬프트 8 — 구현 전달용 정리

확정한 시안을 개발자에게 넘길 수 있게 정리해 줘.
- 값 목록: 색(이름과 값), 글자 단계(크기·굵기·줄 간격), 여백 단위, 모서리, 선
- 부품별 상태: 버튼, 카드, 배지, 입력 칸, 확인 창의 기본·올렸을 때·눌렀을 때·쓸 수 없을 때
- 화면별 구성: 1440폭에서의 단 구성과 최대 폭. 1920폭에서는 어떻게 되는지
- 움직임 표: 무엇이, 언제(스크롤로 들어올 때 / 마우스를 올릴 때 / 누를 때), 어떻게(방향, 거리, 걸리는 시간), 움직임을 줄였을 때는 어떻게 되는지
- 그림 목록: 어느 화면 어느 자리에 어떤 그림이 어떤 크기로 들어가는지
- 영상 인트로와 3D를 넣을 자리, 그리고 그것들을 쓸 수 없을 때 대신 보여줄 정지 그림
